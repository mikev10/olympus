CONTEXT YOU NEED

The runtime drives a model-backed builder through stations. After each build it runs a pinned verification manifest of checks (commands) inside a sandbox; a required check that fails fails the gate and sends the task back to build, up to a fixed number of iterations. This change does two things. First, the next build request after a failed gate carries, in its per-task variable suffix, each failed check's id and the cause the runtime derived (one of a closed set: exit-code, no-result, suite-count, expectation, new-finding, suppression-added), read back from the decision the gate recorded. Second, when a task parks, the run's status reports its latest failure, either a failed attempt or a failed gate, and the event stream publishes each failed gate; a check that could not start carries the error text recorded for it, marked as untrusted.

It must hold against a capable, motivated party trying to steer its own next prompt, or what a person is shown, using output it can influence: to get text produced by its code, its tests, or its container into a later model request, or to make status report a cause other than the one the runtime derived.
