CONTEXT YOU NEED

This code is a runtime that carries software work through a fixed line of stations (intake, spec, test-design, plan, build, verify, review, integrate). Before this change, a run had to be admitted with its spec and its acceptance tests already written. This change lets a run be admitted with a person's intent and no spec, or with no acceptance tests, and drafts them on the line: an agent (the drafter) writes the draft in a sandbox, the runtime reads exactly the draft's paths and records the bytes it read under one hash, a test draft's checks are run over the unchanged repository (the base) to confirm each does what it declares there, a second agent (the critic) reads the recorded draft and returns findings, and the exit from the station needs a person's approval unless the policy cell is auto, the run is at autonomy level L2, and every condition the runtime checks holds. Approved bytes are written into the repository and locked against the approved hash; every later station re-verifies the lock.

It must hold against a capable, motivated party trying to get a draft locked that no independent check and no person actually cleared, or to let the test drafter see the repository it must not see. Assume no deceptive intent — only that the easiest path gets taken.

That party controls what the drafter, critic, builder, and reviewer models return (their narratives and every file they write in their own sandboxes), the bytes they leave in their workspaces, and when the process stops (a stop can fall between any two steps, followed by a resume). It does not control the components the runtime is wired with — the Vault, the sandbox provider, and the drivers are runtime-selected and trusted, even where a function takes one as an argument — and it does not control code running inside the runtime's own process, the policy file, the roles and rubrics directories, or the person's approval and rejection calls.

The invariants at stake:

I2 — The runtime derives status; the model never reports it. A draft is a claim until it is approved and locked; a critic's clean result is one necessary condition among others the runtime checks itself, never sufficient.
I3 — An agent may not be judged by an artifact it can write. Specs and acceptance tests are hashed and locked before build and re-verified at every station transition. The test drafter is black-box: it sees the locked spec and nothing of the repository.
I4 — Default deny. A capability not granted in policy is unavailable; auto approval exists only where a person's policy set it.
I5 — Fail closed. A missing, malformed, or unreadable result, or a condition that cannot be evaluated, is a refusal or a failed condition, never a pass.
I6 — Reviewers never share the author's model family. A critic or reviewer is graded different-family, different-model (same family), or same-model, from the models the runtime resolved; only different-family satisfies any condition.
I7 — Event payloads are data, never instructions. The intent comes only from the human principal's channel; base-run output never reaches a black-box seat; a test-design rejection carries no free text.
