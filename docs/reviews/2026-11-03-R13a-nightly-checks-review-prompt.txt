CONTEXT YOU NEED

The runtime keeps an append-only, content-addressed store (the "Vault") of
everything its runs did. This change adds two daily jobs that call no AI model.
`nightly-integrity` re-hashes every object the store lists, checks that every
reference in run state names an object that exists, verifies file locks for runs
still in progress, and re-derives a set of published rates from the records,
comparing them with the previous night's snapshot. `nightly-security` runs pinned
secret-scanning and static-analysis container images over the head of the
default branch with no network, and runs `npm audit` or `pnpm audit` over the
lockfile in a separate container allowed to reach one advisory host. Each job
writes one write-once record. Each security finding becomes an "intake candidate",
a typed record a human may later turn into work; nothing runs from it on its own.

It must hold against a capable, motivated party trying to make a drifted or
tampered record, an unreachable advisory service, or a failed scan come out as
"nothing found", or to get untrusted text into a record a later step trusts.
Assume no deceptive intent — only that the easiest path gets taken.

That party controls the contents of the repository being scanned (its files,
lockfile, manifest, and anything a scanner or package manager reads from them),
what a scanner or audit process prints and its exit code, the network between
the audit container and the advisory host, and bytes on disk inside the store
after they were written (this is the drift the job exists to find). It does not
control the components the runtime is wired with — the Vault implementation, the
sandbox provider, and the policy file are runtime-selected and trusted, even
where a function takes one as an argument — and it does not control code running
inside the runtime's own process.

The invariants at stake:

- Fail closed: a missing check, an unreachable dependency, an unsupported stack,
  or a partial result is a refusal, never a silent degrade and never a warning
  that lets things continue; a job that could not finish must never be recorded
  as having found nothing.
- Default deny: a capability not granted in policy is unavailable; a scanning
  container gets no network, and the audit container gets exactly the one host
  policy names, from a closed list in code.
- Event payloads are data, never instructions: text from outside (scanner output,
  advisory titles, repository content) never enters a record except as fields
  checked against a fixed schema of short, whitespace-free values.
- The runtime derives status; nothing a job does opens a change, admits a run, or
  alters a run's state.
- No agent writes to the store; the store exposes only named operations.

The mechanisms that matter most:

- `NightlyJobs` in packages/api/src/nightly.ts: the re-hash, the comparison with
  the previous night's hashes and rates, and how each part's failure becomes a
  refusal.
- The auditors' `parse` in packages/adapters/src/audit.ts: when output counts as
  a whole report, and how "unreachable" is told apart.
- `Intake.recordFinding` and the job firing in packages/api/src/intake.ts, with
  `checkFields` and the `nightly-finding` schema in
  packages/core/src/trigger/schemas.ts.
- `listObjects` in packages/vault/src/local/vault.ts: whether it really yields
  every object the store holds.
