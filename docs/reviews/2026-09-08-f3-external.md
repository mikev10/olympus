# External review of F3, 2026-09-08

The triage record for an external adversarial review of the conformance
infrastructure (`packages/conformance`, the two workflows, and the lint
configuration). It records why each finding was or was not acted on, which
`docs/decisions.md` does not capture. Future external reviews get a file in
this directory with the same sections.

## Source

- **Reviewer:** external, adversarial, no repository access; worked from a
  bundle of the repository. The tree at triage time was `bfe0f83` (the F3
  amendment commit) and every finding was checked against it. Line numbers
  in the findings were treated as hints, not citations.
- **Findings returned:** 16. The maintainer's triage grouped them into the
  twelve items below, several with two parts; the reviewer's own numbering
  was not available when this record was written, so the item numbers are
  this record's. The brief noted that at least two findings were self-labeled
  medium confidence; the labels were not passed through with the items, so
  every item was verified on the same footing.
- **Verification:** each finding was checked against the cited file at
  `bfe0f83` before any change. Three type-level claims (items 4, 7, and 8)
  were compiled with the pinned TypeScript 6.0.3 rather than reasoned about.
- **Outcome:** 6 accepted and fixed, 1 part rejected as already true, 6
  recorded as known limits (one of them with the cited mechanism corrected),
  0 unverifiable. Fixes are demonstrated failing before and passing after in
  the commit that carries this record.

## Accepted and fixed

### 1a. CI can pass without running anything

- **Claim:** `.github/workflows/ci.yml` runs `pnpm typecheck`, `pnpm lint`,
  `pnpm test`, and `pnpm conformance`, which resolve to root `package.json`
  scripts; `package.json` is not a protected path, so rewriting the scripts
  to exit 0 makes CI green and trips no guard.
- **Verified:** true as stated. `protected-paths.yml` covered
  `packages/conformance/` wholesale (so that package's manifest and vitest
  config were protected) but not the root manifest, `pnpm-workspace.yaml`,
  any other package's `package.json` (each carries the `typecheck` script CI
  runs), or any other package's test or compiler configuration.
- **Fix:** patterns for `^package\.json$`, `^pnpm-workspace\.yaml$`,
  `^packages/[^/]+/package\.json$`, `^packages/[^/]+/tsconfig(\.[^/]+)?\.json$`,
  and `(^|/)vitest\.(config|workspace)\.`. Per-package `tsconfig.json` was
  added beyond the brief's list because `tsc -p tsconfig.json` reads its
  `include`; an empty `include` typechecks nothing, which is the same attack.
- **Demonstrated:** the guard's pattern block, extracted from the HEAD
  workflow and run over a diff touching those five files, reports no
  protected path; the fixed workflow reports all five. See D-F3-16.

### 1b. The label check is a substring match

- **Claim:** `LABELS` is `join(labels.*.name, ' ')` and the shell matches
  `*" gate-change "*`, so a label named `not gate-change approved` passes.
- **Verified:** true. The match is delimited by spaces, so it is a
  word-in-list match rather than a raw substring match, but the reviewer's
  example is a word in that list and passes.
- **Fix:** `HAS_GATE_LABEL: ${{ contains(github.event.pull_request.labels.*.name, 'gate-change') }}`.
  GitHub evaluates `contains` over an array as element equality. The shell
  reads the boolean only.
- **Demonstrated:** the HEAD `case` statement run with that label prints
  "Allowed"; the fixed shell branches on the boolean alone. The expression
  itself is evaluated by GitHub and was verified against its documented
  semantics, not executed locally.

### 2a. I7 lint rules can be suppressed inline

- **Claim:** the ordinary lint run honours inline configuration
  (`allowInlineConfig` defaults to true and `eslint .` passes no flag), the
  fixture is linted with it off, and `I7.lint-rules-active` reads the
  resolved configuration, which does not see comments. So a
  `// eslint-disable-next-line @typescript-eslint/no-base-to-string` in a
  package source suppresses the rule while both I7 assertions pass.
- **Verified:** true. Demonstrated by planting exactly that comment in
  `packages/core/src/index.ts` at HEAD: `pnpm lint` and `pnpm conformance`
  both pass.
- **Fix:** `I7.lint-rules-not-suppressed-inline` parses every comment in
  every `.ts`/`.js` file under `packages/` outside a `fixtures/` directory
  (from the parsed file, so a directive inside a string or a regular
  expression is not one) and fails on any `eslint-disable`,
  `eslint-disable-line`, or `eslint-disable-next-line` that names an I7 rule
  or names no rule, and on any `/* eslint ... */` configuration comment that
  names one. The bare-disable and configuration-comment cases are beyond the
  brief's wording; both defeat the rules by a different spelling of the same
  comment, so leaving them out would have left the finding open.
- **Demonstrated:** the same planted comment now fails `pnpm conformance`
  with the file and line. See D-F3-17.

### 2b. Enable `reportUnusedDisableDirectives`

- **Claim:** enable it if not already on.
- **Verified:** does not hold. `eslint.config.js` sets
  `linterOptions.reportUnusedDisableDirectives: 'error'` and D-F3-06 records
  why. No change.

### 3. `compileOkSource` accepts annotated errors

- **Claim:** `compileOk` throws when the fixture carries `expect-error`
  annotations; `compileOkSource` calls `assertFixture` directly, so a
  generated source with an annotated error passes.
- **Verified:** true (`assert.ts`, the `compileOkSource` body). The zero
  diagnostics requirement was implicit: with no annotations every diagnostic
  is unexpected. The registry's two generated sources did not carry
  annotations, so nothing was wrong today; the constructor was.
- **Fix:** `compileOk` and `compileOkSource` share `requireClean`, which
  refuses annotations first and then requires zero diagnostics explicitly.
- **Demonstrated:** a unit test with an annotated error resolved at HEAD and
  rejects with `carries expect-error annotations` after. See D-F3-18.

### 4a and 4b. Capability key equality is one-directional; index signatures pass

- **Claim:** `Record<keyof T, 0> = { ...registered }` checks only that every
  registered key exists on `T` and every `T` key is registered when `T` has
  keys. If `T` loses all its keys, `keyof T` is `never`, `Record<never, 0>`
  is `{}`, and the literal is accepted. A string index signature makes
  `keyof T` `string | number`, which accepts any literal.
- **Verified:** true, by compiling both shapes with TypeScript 6.0.3: neither
  reports an error. Demonstrated end to end by emptying
  `DriverCapabilities` at HEAD: `I8.driver-capability-keys-registered`
  passes.
- **Fix:** `keysEqual` generates `Exclude<Actual, Registered>` and
  `Exclude<Registered, Actual>` and requires both to be `never` (tuple-wrapped
  so `never` does not distribute), plus `string`, `number`, and `symbol`
  index-signature checks and a non-empty check. An empty registered set is
  emitted as `never` rather than an empty union. The non-empty check is
  beyond the brief: a capability interface with no keys makes the claims
  section vacuous, and I5 says refuse.
- **Demonstrated:** the emptied interface now fails the registry naming
  `Stale`; seven unit tests cover each direction and each index-signature
  kind. See D-F3-19.

### 5. External assertions verify a substring, not execution

- **Claim:** `verifyExternalAssertion` checks that the package is in the
  workspace, the file exists, and the file contains the quoted id. A README
  with the id in an HTML comment satisfies it; a skipped test satisfies it.
- **Verified:** true, and demonstrated at HEAD with a temporary workspace
  whose `README.md` holds `<!-- 'I1.mount-rejects-second-rw' -->`: the check
  returns no problem. There are zero external assertions in the registry.
- **Fix:** every external assertion is a registry problem until
  reconciliation exists; `verifyExternalAssertion` and the `root` option are
  removed; `stateOf` counts local assertions only, so an entry with nothing
  but a refused external assertion is `missing`. The reconciliation
  requirement is `I8.external-assertion-execution-reconciled`, pending, owner
  P2, and I8's baseline is raised from 0 to 1 for it.
- **Demonstrated:** the unit test that a registry holding an external
  assertion reports the refusal fails at HEAD (no problem reported) and
  passes after. See D-F3-20.

### 6. I6's pending condition permits violating I6

- **Claim:** the pending reason for `I6.review-seat-family-check` says
  "refuse a reviewer whose family equals the author's, or record reduced
  independence when only one family is available"; the second branch is
  satisfied while a same-family reviewer is seated.
- **Verified:** true (`i6.ts`). The spine's I6 text has the same "or"; the
  maintainer's decision resolves it by level.
- **Fix:** the reason now states that at L0-L2 the seat may be filled by the
  same family and the gate result must record reduced independence, and that
  at L3 a same-family reviewer is refused and reduced independence is not
  reportable. Both halves must be asserted by P4.
- **Demonstrated:** a meta-test that the obligation names both halves and no
  longer contains the "or record reduced" branch fails at HEAD and passes
  after. See D-F3-21.

## Recorded as known limits (D-F3-22)

### 7. Spread-and-widen on `TaskResult`

- **Claim:** `{ ...result, status: 'passed' }` sidesteps excess-property
  checking, so the I2 fixture proves a `status` field cannot be written, not
  that a `TaskResult` cannot carry one.
- **Verified:** the mechanism as cited does not hold under TypeScript 6.0.3:
  an object literal with a spread is still fresh, and `status` in that
  position is rejected with TS2353. The structural point holds through any
  non-fresh value: the same literal assigned to a variable first, a cast to
  a subtype with the extra field, or a generic parameter bounded by
  `TaskResult` all compile and all deliver a value carrying `status`.
- **Disposition:** recorded with the corrected mechanism. Runtime validation
  of a driver's `TaskResult` at the boundary is owed to P6, which is where
  status is derived (I2).

### 8. Erasure evades the cast scan

- **Claim:** widening to `unknown` by annotation or parameter, erasure
  through a generic parameter, and a type predicate all reach a string with
  no cast from `UntrustedText` for the scan to see.
- **Verified:** the `unknown` forms were already recorded (D-F3-06,
  D-F3-15). The generic form (`erase<T>(x: T): unknown`, then `as string`)
  and the predicate form (`x is string` narrowing `raw` to
  `UntrustedText & string`) compile and are not reported.
- **Disposition:** recorded. Sink-level enforcement is the pending
  `I7.untrusted-sink-lint-rule`, owner M2.

### 9. Baseline ratchet slack

- **Claim:** a decrease followed by an increase back to the original number
  passes.
- **Verified:** true, and already recorded as the accepted tradeoff in
  D-F3-13 (decreases always allowed; the delta line and CONTRIBUTING make the
  slack visible).
- **Disposition:** no change.

### 10. Incomplete inventory

- **Claim:** `packageProgram` reads each package's `tsconfig.json`
  `include`, and `workspacePackages` reads one directory level under
  `packages/`, so a source file outside `include` or a package nested deeper
  is never scanned by I7, I9, or I10.
- **Verified:** true. Every non-conformance package today has
  `include: ["src"]`, so a `test/` directory in one of them would be outside
  its program; the spine's `drivers/claude-code` package, if placed under
  `packages/drivers/`, is outside both the workspace glob and the scan.
- **Disposition:** recorded. Owed to P5, the first unit that adds a package
  outside one level under `packages/`; the fix is to derive the inventory
  from the workspace globs and to assert that every source file under a
  package directory is in that package's program.

### 11. I9 matches spellings

- **Claim:** `const { stdout } = process; stdout.write(...)` contains no
  `process.stdout` chain and passes.
- **Verified:** true (`propertyChains` reports dotted access rooted at an
  identifier; destructuring produces none).
- **Disposition:** recorded. Binding-level resolution through the checker is
  owed to P9, where the API's headless assertion lands.

### 12. I10 is finite and partial

- **Claim:** the Greek list is curated and the scan reads only some
  surfaces, so the invariant's "never appear in code" is broader than what
  is asserted.
- **Verified:** true. The precise policy is recorded in D-F3-22.
- **Disposition:** recorded; the assertion title and D-F3-07 already state
  the exemptions, and the decision now states what is and is not scanned.
