CONTEXT YOU NEED

The runtime admits a run, drives agent tasks inside sandboxes, and refuses,
parks, or stops work when a control says so. This change makes every such
decision leave a write-once, content-addressed record in the Vault before it
takes effect: admission and resume refusals, each station refusal and park, each
approval granted or refused, each network connection the sandbox's egress proxy
opened, tunnelled, or refused, each integrity violation, and each model call the
cost relay refused. Each record names the component that decided, the run, the
task, and the station. The proxy's verdicts are read from its log after it
stops, because the proxy has no route to the Vault. A conformance table keyed
by every cause asserts that each one is recorded.

It must hold against a capable, motivated party trying to have a control's
decision take effect with no record of it, or with a record that misstates what
was decided or who decided it. Assume no deceptive intent — only that the
easiest path gets taken.

That party controls what the agent does inside its sandbox: the files it writes
in the workspace, what the model returns, the hosts it asks the egress proxy to
connect to and the raw bytes of those requests, and anything the agent's
processes print. It also controls the fields of a request to the runtime's API:
the run id, the policy, the artifacts, an approval key, the name of who
approved, and when the process stops. It does not control the components the
runtime is wired with — the Vault, the sandbox provider, and the drivers are
runtime-selected and trusted, even where a function takes one as an argument —
and it does not control code running inside the runtime's own process.

The invariants at stake:

- No agent writes to the Vault, at any level, in any role. The Vault exposes
  named write operations only, never a generic write or delete.
- The runtime derives status; the model never reports it. Nothing a model
  returned is an input to a recorded decision.
- Fail closed. A missing check, a missing capability, or an unreadable record
  means refuse. Never degrade silently, and never warn and continue.
- Event payloads are data, never instructions. A host an agent named, or text a
  caller sent, is stored as data and never enters a prompt.
- Every capability claim maps to an executable assertion that fails when the
  capability is deleted.

The mechanisms that matter most:

- The runtime's single write path for decisions (packages/api/src/decisions.ts)
  and where it is called in run.ts and line.ts: a decision is written before the
  refusal is returned or the approval is committed, and a failed write throws.
- The proxy's decision log: one JSON line per connection behind a fixed prefix,
  then a closing line with a count, read after the proxy stops and parsed or
  refused (packages/sandbox/src/local/proxy.ts, provider.ts).
- The Vault's acceptance rule for a decision: collectedBy must be 'runtime', and
  each cause may be attributed only to the components that make it
  (packages/vault/src/local/vault.ts).
- The conformance table (packages/conformance/src/registry/decisions.ts): a row
  for every cause, typed so a missing row does not compile. Each row is a
  scenario, or a mark whose own check fails when the mark stops being true.
