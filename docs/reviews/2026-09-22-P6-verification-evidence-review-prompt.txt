CONTEXT YOU NEED

An agent (driven through a `Driver`) does a build task inside a sandbox, and the
runtime then decides, without asking the agent, whether the task passed. This
change moves every task off the author's own working copy onto trees the runtime
owns: the working tree is snapshotted as a base at admission, each build attempt
runs over a fresh copy of base plus the diff accepted so far, the runtime
collects the task's own diff by comparing directory trees in process, and the
pinned verification checks run over a tree built from base and the cumulative
diff, mounted read-only with no network. The diff is held to the locked
artifacts and to the task's writable globs, the agent's claim is diffed against
it, suite counts are taken from files on the host, and an evidence bundle
recording all of it is written to the Vault. It also narrows what a review
seat's workspace holds, records at admission which verification controls the
repository's stack lacks, and makes a sandbox's container user explicit.

It must hold against a capable, motivated party trying to get a task recorded
as passed without the work the pinned checks require, or to reach a file,
capability, or later task it was not granted. Assume no deceptive intent — only
that the easiest path gets taken.

That party controls what the model does inside its sandbox (every file it
writes, every process it starts, every command it runs, including processes it
leaves running), the contents of the repository it is handed, and every field of
the `TaskResult` a driver returns, which may carry keys the type does not name.
It does not control the components the runtime is wired with — the Vault, the
sandbox provider, the drivers, and the workspace store are runtime-selected and
trusted, even where a function takes one as an argument — it does not control
the verification manifest, the spec, the acceptance tests, or the task graph,
which are hashed and locked before it runs, and it does not control code running
inside the runtime's own process.

The invariants at stake:

- The runtime derives status; the model never reports it. A task's status is
  computed from the results of checks the runtime ran. A driver's result has no
  status field; the agent's narrative is a claim, stored separately from the
  evidence, and the two are diffed.
- An agent may not be judged by an artifact it can write. Specs and acceptance
  tests are hashed before build and re-verified at every station transition.
- Default deny. A capability not granted in policy is not available — including
  a path outside the task's writable globs, and anything an earlier task leaves
  behind for a later one.
- Fail closed. A missing required check, a shrunken suite enumeration, an
  unrepresentable command, an unwritable workspace, or an unsupported stack is a
  refusal — never a silent degrade, never a warning that lets the run continue.
- Reviewers never share the author's model family, and a review seat reads only
  the context its station contract grants — never the author's narrative or the
  plan.
- No agent writes to the Vault, at any level, enforced at the mount layer.

The mechanisms that matter most:
