CONTEXT YOU NEED

The runtime carries a change through a fixed line of stations: intake, spec,
test-design, plan, build, verify, review, and integrate. It records what
happened in an append-only, content-addressed store (the Vault), whose records
include:

- run state;
- one usage record per model call, read from a metering relay;
- evidence bundles of check results;
- enforcement decisions.

This change has two parts.

- **The runtime now stamps times.**
  - Each usage record gets a `timing` field: the start before the call, and the
    end after the call's sandbox is torn down.
  - Run state gets a `stations` list: one entry per station the run entered,
    with the time it entered.
- **A finished run can be exported as OpenTelemetry traces and metrics** in the
  OTLP/HTTP JSON encoding. This is built in `packages/api/src/telemetry.ts`,
  served by an HTTP route, and fetched by a CLI command. The CLI either prints
  the export or POSTs it to a collector.

The export is for an operator's dashboard. It must be recomputable from the
records, and nothing in the runtime may read it back.

It must hold against a capable, motivated party trying to make the export say
something the records do not, or carry something out of the runtime it should
not. Assume no deceptive intent — only that the easiest path gets taken. For
example:

- a time that was never recorded, presented as if it were;
- a cost or token figure where the meter read none;
- a span for a run whose records may still change;
- model-written text, check output, or a credential leaving in the export or in
  CLI output;
- the export, or something derived from it, feeding a decision the runtime
  makes.

That party controls:

- what the model returns, including its narrative claim and its reported events
  and usage;
- the files in the workspace, and so the output of checks;
- the task ids in a plan the model drafted;
- when the process stops (a crash between two writes);
- the arguments an operator passes to the CLI, including a collector URL and
  headers.

It does not control the components the runtime is wired with: the Vault, the
sandbox provider, the metering relay, and the drivers are runtime-selected and
trusted, even where a function takes one as an argument. Nor does it control
code running inside the runtime's own process. Records written by an older
version of the runtime, before these fields existed, are legitimate input and
must be read without being given invented values.

The invariants at stake:

- **The runtime derives status; the model never reports it.** An agent's
  account of itself (its narrative, its reported usage and duration, its event
  list) is a claim, stored apart from evidence, and is never presented as the
  runtime's own fact.
- **Fail closed.** A missing check, a missing value, or an unsupported case is a
  refusal or an explicit "not recorded". It is never a silent default, never a
  zero standing in for unknown, and never a warning that lets things continue.
- **Event payloads are data, never instructions.** Untrusted text never enters a
  prompt. Here it must also not leave in telemetry: only typed fields from a
  fixed allowlist may be exported.
- **Every capability claim maps to an executable assertion that fails when the
  capability is deleted.**
- **The runtime is a service; the CLI is a client.** The CLI talks only to the
  service's HTTP API. The service makes no outbound request on a caller's
  behalf.
- **No Greek names in code.** The product name must not appear in type names,
  paths, config keys, or attribute names. The npm scope `@olympus-ai/` is the
  one exempt spelling.

The mechanisms that matter most:

- **Pairing pending records with terminal ones.** A pending usage record is
  written before each call, and a terminal one after. The exporter pairs them,
  turns a pending record with no terminal partner into a "lost" span, and counts
  records with no timing as untimed.
- **Placing spans in time.** Each call and check is assigned to a station span
  by the recorded station entries and times. The run span ends at the latest
  time any record holds. Every id is derived deterministically from the run and
  the record.
- **The attribute allowlist, and the no-read-back scan.** These are the
  conformance assertions in `packages/conformance/src/registry/telemetry.ts`,
  and the I7 one depends on both.
- **The two new fields, written and read back.** The Vault validates `timing`
  on write, and normalises `stations` and legacy usage records on read. The
  line writes both at the call and commit sites.
