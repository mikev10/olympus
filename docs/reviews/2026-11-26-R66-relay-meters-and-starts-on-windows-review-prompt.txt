CONTEXT YOU NEED

A model runs a task inside a container that has no route to the internet. Every model request it makes goes through a relay the runtime owns: a Node program (`RELAY_SOURCE` in packages/sandbox/src/local/relay.ts) running in its own container, which holds the model credential, forwards requests upstream, reads the usage each answer reports, prices it from a table the runtime gives it, and refuses further requests once the task's budget is spent or once it meets an answer whose cost it cannot count. It speaks three dialects: `anthropic-messages`, `openai-chat`, and `openai-responses`. This change does three things. First, a price table naming a model whose id marks it as one that performs a web search on every call, billed per search outside the token counts, is refused before any container starts (`PER_CALL_MODEL` and `checkMeter`), and again by the relay's own start checks. Second, the `openai-responses` dialect now reads the service tier an answer reports, from a whole body and from a stream's `response.completed` event, and stops forwarding after an answer served at any tier but `default`, because the price table holds the default rate alone. Third, the relay's source no longer travels as a command-line argument: the container is created with `docker create --interactive … node -` (`relayCreateArgs`) and started with the source written to its standard input (`dockerStartWithInput` in packages/sandbox/src/local/docker.ts, `startRelay` and `requireListening` in relay.ts), because as one argument it came within reach of the 32,767-character Windows command-line limit. `windowsCommandLineLength` measures the line Windows would be handed, and tests hold each shipped relay's argument list under the limit.

It must hold against a capable, motivated party trying to spend money the budget does not see, or to change what the relay container runs or can reach. Assume no deceptive intent — only
that the easiest path gets taken.

That party is the model doing a task, inside the task's container. It controls the requests it sends to the relay (path, headers, body, including which model and options a request names), how many it sends and when, the files in its working copy, and when its process stops.
