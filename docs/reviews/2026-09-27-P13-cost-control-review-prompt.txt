CONTEXT YOU NEED

The runtime runs each agent task in a Docker sandbox. The sandbox has no network route except a "model relay": a separate container the runtime starts beside it. The relay holds the API credential and forwards the sandbox's requests to the model vendor's API. This change makes the relay count each call:
- It reads the model named in each request and the token usage each response reports.
- It prices each call from a table the driver supplies.
- It refuses every request once the task's token budget or dollar budget is spent.

When the sandbox is destroyed, the runtime reads the relay's count and records one usage record per agent invocation in the Vault. The Vault is the runtime-only store agents cannot write to. Totals per task, station, and run are computed from those records alone. The agent's own report of what it used is not trusted as a source of cost.

The code must hold against a capable, motivated party trying to spend more model money than the task's budget allows, or to make money that was spent go unrecorded or be recorded as less than it was. Assume no deceptive intent — only that the easiest path gets taken.

That party is the task: the model and the CLI running inside the sandbox, and any process they start there. It controls:
- every HTTP request any process in the sandbox sends to the relay: method, path, query, headers, body, how many requests, how concurrently, how fast, and when connections close;
- the files and processes inside the sandbox;
- whatever the agent returns as its result, including the usage figures it reports;
- through its prompts, the text content of the model's responses. That text arrives inside the vendor's response bodies as JSON-escaped strings.

It does not control:
- the relay container's code, environment, or log;
- the Docker host, the sandbox provider, the Vault, the drivers as constructed, or the runtime process. These are runtime-selected and trusted, even where a function takes one as an argument;
- the structure of the vendor's responses, as opposed to the model's text inside them;
- when the runtime destroys the sandbox.

The invariants at stake:

- Default deny. A capability not granted in policy is unavailable. Spending model money is a capability, bounded here by a per-call budget of tokens and dollars.
- The runtime derives status and facts; the model never reports them. What a call cost must be collected by the runtime from a component outside the sandbox, never taken from the agent's own report.
- Fail closed. A missing check, missing capability, unreadable measurement, or misconfiguration is a refusal. It is never a silent degrade, and never a warning that lets the run continue. Anything the meter cannot count must be charged or refused, never forwarded free.
- Every capability claim maps to an executable assertion that fails when the capability is deleted. A test that would pass with the mechanism removed is a defect.
- No agent writes to the Vault. Records reach it only through named operations the runtime calls.
- Event payloads are data, never instructions. Nothing the relay reads enters a prompt.

The mechanisms that matter most:

- The relay's request classification (metered, free, or refused), the buffering and parsing of the request's `model` and `max_tokens`, and the parsing of streamed (server-sent events) and whole JSON responses for usage. All of these are in `RELAY_SOURCE` in `packages/sandbox/src/local/relay.ts`.
- The budget check and charge: when totals are updated, when requests are refused, the one-call-at-a-time queue, how an unreadable or partial response is charged, and what happens to in-flight calls on SIGTERM.
- The read of the meter at teardown: the provider's `destroy` and `#dismantle` in `packages/sandbox/src/local/provider.ts`, and `readMeter` and `meterReadingFrom` in `relay.ts`. The relay's stdout log is the channel, and the reading is the sum of its per-call lines checked against a closing line.
- The recording path: `runTask` and `recordUsage` in `packages/api/src/line.ts`, `LocalVault.recordUsage`, and `costTotals` and `readUsage` in `packages/api/src/cost.ts`.
