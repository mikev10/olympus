CONTEXT YOU NEED

The project runs AI coding agents on a fixed line of stations and judges their
work from evidence the runtime collects itself. This change adds a second
agent driver, `packages/drivers/codex`, which runs the OpenAI Codex CLI
(pinned to 0.166.0) inside a Docker sandbox the runtime provisions. The model
credential is held by a separate relay container that forwards the CLI's
requests to the API and meters each one against a per-task budget; this change
teaches that relay a third API dialect, OpenAI's Responses API
(`packages/sandbox/src/local/relay.ts`, `packages/sandbox/src/types.ts`).
Before every task the driver runs the same CLI invocation once against a
capture endpoint on the sandbox's loopback, reads the request the session would
send, and refuses unless its tools equal the task's grant, its model is the one
the runtime chose, and its credential is the placeholder; then it runs the task
for real through the relay. Every source of instructions the CLI reads from its
working tree is meant to be off. The conformance registry
(`packages/conformance/src/registry/`) names assertions in the driver's test
files that must pass for each capability the driver claims.

It must hold against a capable, motivated party trying to obtain a capability
it was not granted, or to spend more than its budget unnoticed, or to change
what instructs a later task, from inside a task. Assume no deceptive intent —
only that the easiest path gets taken.

That party controls what the model returns, every command the model runs inside
the sandbox while the task runs (as the sandbox's uid, with the workspace
writable), every file in the workspace — including files an earlier task left
there for a later one — and anything it can leave running in the container.
It does not control the components the runtime is wired with — the sandbox
provider, the relay's code and configuration, the image's root-owned files,
and the driver itself are runtime-selected and trusted, even where a function
takes one as an argument — and it does not control code running inside the
runtime's own process. The vendor's API is trusted to report usage honestly.

The invariants at stake:

- No agent writes to the Vault (the runtime's record store). It is kept out of
  the sandbox at the mount layer.
- An agent may not be judged by, or instructed by, an artifact it can write. No
  file in the workspace may reach a later task's instructions.
- Default deny. A tool or capability not granted to the task is unavailable to
  the model, not merely unused.
- Fail closed. A missing check, an unreadable result, usage that cannot be
  counted, or an unsupported configuration is a refusal, never a silent degrade.
- Reviewers never share the author's model family. A driver's family is a value
  it states explicitly, never inferred from a model name.
- Every capability claim maps to an executable assertion that fails when the
  capability is removed.
