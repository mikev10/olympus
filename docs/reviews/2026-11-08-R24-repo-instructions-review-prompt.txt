CONTEXT YOU NEED

The runtime carries a change through a fixed line of stations (spec,
test-design, plan, build, verify, review, integrate), seating model agents at
some of them. This change reads a fixed list of the target repository's
instruction files (CLAUDE.md and AGENTS.md at the root, .claude/rules/*.md, and
each SKILL.md under .claude/skills/ and .agents/skills/) from the snapshot of
the base taken when a run is admitted, refuses admission on a file it will not
read, pins every file's path, hash, and text in the admission record, and gives
the text to a seat only where the station's contract allows a new context grant,
'repo-instructions', and the seat's role scope in policy sets
repoInstructions. At autonomy levels L0 to L2 the text is placed at the start of
the seat's cacheable system prefix; above L2 it first narrows the run's
capabilities through an existing narrowing API, and is placed only in the
per-task suffix.

It must hold against a capable, motivated party trying to use the target
repository's files to change what a seat is allowed to do, to change what a
later seat of the same run is told, or to put text in front of the seat that
writes the acceptance tests. Assume no deceptive intent — only that the easiest
path gets taken.

That party controls the contents of the target repository at admission
(including links, directories where files are expected, oversized or non-UTF-8
files, and front matter), everything a model writes into its task's workspace
during the run, and later commits to the target repository. It does not control
the policy document, the roles directory, or the components the runtime is
wired with — the Vault, the sandbox provider, the workspace store, and the
drivers are runtime-selected and trusted, even where a function takes one as an
argument — and it does not control code running inside the runtime's own
process.

The invariants at stake:

- An agent may not be judged by an artifact it can write. Specs and acceptance
  tests are hashed before build and re-verified at every station transition;
  here, nothing a task writes may change what a later task of the same run is
  given.
- Default deny. A capability not granted in policy is unavailable. Nothing in a
  target's file may widen or narrow a grant.
- Fail closed. A missing check, a file the reader refuses, or a record that
  does not verify is a refusal, never a silent degrade, a skip, or a
  truncation.
- Event payloads are data, never instructions: untrusted text never enters a
  system or role prompt. Above L2 the target's instruction text is treated as
  such input and placed only after the run is narrowed, in the per-task suffix.
- The seat at test-design is given the locked spec alone, so the acceptance
  tests are written from the spec and nothing else.
