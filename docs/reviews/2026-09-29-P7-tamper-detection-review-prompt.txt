CONTEXT YOU NEED

Each agent task runs in a fresh copy of the repository. When it finishes, the
runtime diffs the copy against what it handed the task, builds a tree from that
diff, and runs pinned checks over that tree. This unit adds `analyzeTamper`
(packages/api/src/tamper.ts), which compares the tree the task was handed with
the tree its checks ran over and reports what the task did to the tests that
judge it: weakened, removed, or tolerance-widened assertions; added skip, only,
todo, and similar markers; deleted test cases, where a case moved or renamed
elsewhere is not a deletion; regenerated snapshot files; protected-path and
config-file changes; and changed-line coverage. Parsing goes through a
per-framework adapter for vitest and jest (packages/adapters), which gains
`enumerateCases` here. The line (packages/api/src/line.ts) records each kind of
finding as an integrity violation, stores the report in the task's evidence
bundle, shows the findings to the review seat, and raises the approval required
to leave the `integrate` station to a human (packages/core/src/station/machine.ts,
packages/api/src/run.ts). A finding does not fail or halt the run by design.

It must hold against a capable, motivated party trying to change, skip, or
remove the tests and checks that judge its work, or change what a pinned check
command actually runs, while the tamper report comes back empty or incomplete.
Assume no deceptive intent — only that the easiest path gets taken.

That party controls the contents of every file it writes in its own workspace
copy, within the paths its role may write — test files, source files, framework
and package configuration, snapshot files — including their names, their
locations, and their syntax, and it controls the result object its driver
returns. It does not control the components the runtime is wired with — the
Vault, the sandbox provider, the workspace store, and the drivers are
runtime-selected and trusted, even where a function takes one as an argument —
and it does not control the tree it was handed (the base), the policy, the
pinned check list, or code running inside the runtime's own process.

The invariants at stake:

An agent may not be judged by an artifact it can write. Specs and acceptance
tests are hashed before the build and re-verified at every station transition;
this unit extends the principle to the repository's own tests and the
configuration that decides what a check runs.

Fail closed. A missing check, an absent capability, an unsupported stack, or a
shrunken suite is a refusal — never a silent degrade, never a warning that lets
the run continue. An input the analysis cannot read must not read as an input
with no findings.

The runtime derives status; the model never reports it. The report is the
runtime's reading of the diff it collected, never the driver's account of it.

No agent writes to the Vault, and nothing on the host executes repository code:
the analysis parses files and must not load or run any of them.

The mechanisms that matter most:

- test-file selection: which files are read on each side (changed, or a test on

- pairing across files: assertions, markers, and case titles matched as

  and extended test declarers
- the escalation path: report stored in the evidence bundle, read back from the
  Vault at the `integrate` exit and by the status view, and turned into a
