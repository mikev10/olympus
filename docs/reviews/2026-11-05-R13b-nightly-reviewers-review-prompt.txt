CONTEXT YOU NEED

The runtime carries work from a request to merged code through fixed stations, with AI models in the seats, and records everything it decides in a store the models cannot write. This change adds two nightly jobs (packages/api/src/nightly-review.ts, dispatched from nightly.ts). `nightly-findings-review` gives a reviewer model one UTC day of the runtime's own records, projected to typed fields. `nightly-tree-review` gives a reviewer model the whole tree at the head of the default branch, read-only. Each reviewer answers in JSON. Each finding it reports becomes a candidate that a person may admit as new work, but only once the runtime has checked the finding against what it reviewed. The reviewer's free text is kept as a record of what it claimed. Each seat's model family is compared with the families of the models that authored the work under review.

It must hold against a capable, motivated party trying to get untrusted text in front of a model as instructions, to get a finding recorded that the runtime never located, to have a reviewer judge work from its own model family while the record claims independence, or to have a nightly job change a run, a grant, or the store. Assume no deceptive intent — only
that the easiest path gets taken.

That party controls what the reviewer model returns (its whole final message and the model identity its result names), the contents and file names of the repository tree being reviewed, and the free-text fields of the records the runtime made during the day: messages, details, hosts an agent chose, check ids a drafting model may have written, and a violation's detail. It does not control the components the runtime is wired with — the store (Vault), the sandbox provider, the policy, the roles directory, and the drivers are runtime-selected and trusted, even where a function takes one as an argument — and it does not control code running inside the runtime's own process.

The invariants at stake:

- Reviewers never share the author's model family. Where they must because only one family is available, the system records reduced independence rather than claiming the guarantee. At the highest autonomy level, a same-family reviewer is refused.
- Event payloads are data, never instructions. Untrusted text enters inside an envelope and is never concatenated into a system or role prompt.
- Fail closed. A missing check, an absent capability, or an unreadable result is a refusal: never a silent degrade, never "nothing found".
- Default deny. A capability not granted in policy is not available.
- The runtime derives status; the model never reports it. What a model says is a claim, stored apart from evidence, and never decides anything.
- No agent writes to the store. Nothing a sandbox can reach writes it.

The mechanisms that matter most:

- `dayItems` and `decisionFields`: what of each record reaches the findings reviewer's prompt.
- `readReviewResult`, `elementFields`, and the per-finding checks in `findingsReview` and `treeReview`: the schema check (packages/core/src/trigger/schemas.ts), the record-id membership check, and the tree location check (path held, line within the file).
- `seatOnce` and `grade`: role compilation, the policy scope, the sandbox spec (mount, egress, relay), and the independence grade before and after the call. `authorsOf` and `mergedSince` decide who counts as an author.
- `NightlyRecord.review` (packages/vault/src/types.ts): what is persisted, and whether a reviewer's claim can reach a later prompt.
