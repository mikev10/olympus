CONTEXT YOU NEED

The runtime carries a change through fixed stations: build tasks are run by an AI model (the author) in a sandbox, checks run, and then review tasks are run by a model (the reviewer) that judges the change. This code records each seat's identity — the role it ran under, the driver (the vendor harness, named by its provenanceId()), and the model — and refuses to seat a reviewer that is the same identity as an author of the change. It also adds a second seat beside every review task, a security reviewer, derived from the task graph so no graph can name or omit it, run under its own role with a narrower set of context than the reviewer gets. Every driver call's usage record now names the driver the call went through, and records written before this change are read as "not recorded". The host can also place the Codex driver (a second model family) in seats an operator names.

It must hold against a capable, motivated party trying to have a change reviewed by itself, or by a reviewer that saw what it must not see, while the run's records say the review was independent. Assume no deceptive intent — only that the easiest path gets taken.

That party controls what a model returns (its result, including the model identity it reports, and its narrative), the files a build task writes in its workspace, the task graph and verification files a person supplies, and when the process stops. It does not control the components the runtime is wired with — the Vault (the record store), the sandbox provider, and the drivers are runtime-selected and trusted, even where a function takes one as an argument — and it does not control code running inside the runtime's own process, nor the host's environment variables.

The invariants at stake:

- Reviewers never share the author's model family. Where only one family is available, the system reports reduced independence rather than claiming the guarantee. A model's family is declared, never inferred.
- The runtime derives status and records; the model never reports them. What a driver returns is a claim, never the record.
- Default deny: a capability, context grant, or credential not granted is unavailable.
- Fail closed: a missing check, a missing record, or an unsupported case is a refusal, never a silent degrade or a warning that lets the run continue.
- No agent writes to the record store, and no credential the host holds (the merge token, the API's local token, a model key) reaches a sandbox.

The mechanisms that matter most:

- seatReviewer in packages/core/src/station/machine.ts, and authorsOf and review in packages/api/src/line.ts: who counts as an author, how identities are compared, and which seat is committed.
- parseGraph in packages/api/src/validate.ts: the derived `.security` task beside each review task, the reserved suffix, and the refusal of a build task under a reviewing role.
