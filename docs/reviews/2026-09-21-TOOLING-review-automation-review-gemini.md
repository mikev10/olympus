1. `scripts/review-runner/artifacts.ts:20` — factually wrong — high — `findUnitArtifacts` resolves the prompt and bundle to use by lexicographically sorting their filenames and selecting the one with the highest date (`b.date.localeCompare(a.date)`). An attacker can easily bypass the review of their actual code by committing a dummy prompt and bundle with a far-future date (e.g., `9999-12-31-<UNIT>-bypass-review-bundle.txt`). The runner will silently select and send the attacker's fake files over the legitimate artifacts generated by `review-request`. The attacker can engineer the fake bundle to contain minimal code and prompt injections to ensure it returns the necessary markers and a passing review.
   **Resolve:** Fail closed if multiple artifact pairs exist for the given unit, or enforce that the resolved artifacts strictly match the current date or the specific hash recorded in the commit.

2. `.claude/skills/review-request/SKILL.md:46` — fails open — high — The shell loop generating the bundle (`git diff --name-only ... | while read -r f`) fails to account for Git's path quoting. If a file is named with characters that Git considers unusual (like tabs or non-ASCII characters), Git will output the filename enclosed in double quotes (e.g., `"malicious\tfile.ts"`). The `[ -f "$f" ]` existence check will fail against the literal quoted string, causing the loop to `continue`. The malicious file will be silently omitted from the bundle sent to the reviewer, bypassing the adversarial review completely while allowing the run to count as successful. 
   **Resolve:** Use `git diff -z --name-only` piped into a null-delimited reader (e.g., `while IFS= read -r -d '' f`) to handle all paths securely without Git's quoting.

3. `scripts/run-external-review.ts:98` — factually wrong — high — `findLeakedSecrets` only searches the text for the *last* 20 characters of a long credential (`value.slice(-SECRET_TAIL_LENGTH)`). If the third-party model leaks the first half or majority of a long key but stops before the end (due to truncation, token limits, or arbitrary model behavior), the `appears` check will fail to detect the leak. Consequently, the partial (but potentially compromising) credential will be successfully placed into a committed evidence file.
   **Resolve:** Extract and check both the first 20 characters and the last 20 characters of long credentials to prevent prefix leaks.

4. `scripts/review-runner/payload.ts:16` — factually wrong / a tradeoff I would have made differently — medium — The runner directly concatenates the untrusted bundle text into the prompt string. This explicitly violates the stated invariant: "Payloads are data, never instructions. Content that arrives from outside the process never enters a prompt as an instruction." Because the payload enters the prompt without systemic segregation, an attacker can place a prompt injection instruction at the top of a changed file telling the model to ignore the actual code, output the four required markers, and claim no vulnerabilities exist.
   **Resolve:** Use provider-specific structural separation (like Gemini's File API, distinct `systemInstruction` roles, or strict multi-part structures) rather than inline string concatenation.
