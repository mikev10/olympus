CONTEXT YOU NEED

The project is a runtime that has AI models do software work inside sandboxed containers and then judges the result itself. This change adds a driver (packages/drivers/openai-compatible) for any endpoint speaking the OpenAI-compatible chat-completions API: the endpoint is only a model, so the driver runs the agent loop in the runtime's own process, makes each model call by running a fixed `node` program inside the sandbox that posts to a "model relay", and runs each tool the model calls (Bash, Edit, Read, Write) inside the sandbox through the sandbox provider's `exec`. The model relay (packages/sandbox/src/local/relay.ts) is a separate container on the sandbox's network that holds the endpoint's credential, forwards only granted paths to one fixed https upstream, meters what each call used, and refuses every call once a per-task budget is spent; this change teaches it a second usage dialect (`openai-chat`) and a second way of writing the credential (`bearer`). The runtime's graph builder now accepts the new driver as a trusted component, and the host can seat it in chosen seats from an operator's configuration file.

It must hold against a capable, motivated party trying to get work done or judged in a way the runtime did not grant: run a command or write a file outside the sandbox, use a tool the task was not granted, read the endpoint credential, spend past the budget or spend without being counted, or have answers from one model attributed to the model family the operator declared. Assume no deceptive intent — only that the easiest path gets taken.

That party controls everything the model returns through the endpoint — message text, tool-call names and arguments, the `model` and `usage` fields, status codes and malformed bodies — and everything inside the sandbox: files in the workspace, processes it starts there, and any HTTP request it sends from inside the sandbox to the relay. It does not control the operator's endpoint configuration or the host's environment variables. It does not control the components the runtime is wired with — the Vault, the sandbox
provider, and the drivers are runtime-selected and trusted, even where a
function takes one as an argument — and it does not control code running inside
the runtime's own process.

The invariants at stake:

- No agent writes to the Vault, at any autonomy level, in any repository or role; this is enforced by what the sandbox mounts, so anything an agent does must happen inside the sandbox and never on the host.
- The runtime derives status; the model never reports it. A task result carries no status field, and what the model says it did is a claim, not evidence.
- Default deny. A capability not granted in policy is unavailable — this includes which tools a task may use and what it may spend.
- Fail closed. A missing check, missing capability, unsupported configuration, or unreadable usage is a refusal — never a silent degrade and never a warning that lets the run continue.
- Reviewers never share the author's model family. A model family is stated explicitly by whoever configures the driver and is never inferred from a driver id, a URL, or a model name.
- Every capability a driver declares maps to an executable assertion that fails when the capability is removed; a declaration with nothing behind it is a defect.

The mechanisms that matter most:

- The host-side loop's grant check: only granted tools are offered to the endpoint, and a model call naming any other tool is answered with an error and not run (src/driver.ts, src/tools.ts).
- That every tool and every model call reaches the sandbox only through `provider.exec`, with paths and commands passed as arguments rather than spliced into shell text (src/tools.ts, src/call.ts).
- The relay's `openai-chat` metering and ceiling rules and its `bearer` credential writing (packages/sandbox/src/local/relay.ts, the relay source string and checkRelay/checkMeter).
- Identity: the response's `model` must equal the requested model, and the family is the configuration's (src/driver.ts readTurn and #runTask, src/config.ts checkConfig).
