CONTEXT YOU NEED

A coding agent runs inside a Docker sandbox. Its only route to the model
provider is a relay: a separate container that holds the API credential, which
the sandbox never sees, forwards granted paths to one upstream, and meters every
call against a budget. The provider's Messages API can run some tools itself,
web search among them, outside the sandbox and billed per use outside token
usage. This change adds a grant of such "server tools" to the relay's
specification (`RelaySpec.serverTools`, each entry an exact tool `type` and a
per-use price). The driver derives the grant from the task's granted tools
(`Driver.relayRequest(tools)`). The relay refuses any request offering a typed
tool the grant does not name, or naming `mcp_servers` or a `container`, and
charges each granted use against the budget. The relay's source runs as a
single `node --eval` argument, and the shipped copy is the source with
whole-line comments and indentation stripped.

The relay must hold against a capable, motivated party trying to obtain a
capability that was not granted: to make the provider's API run a tool the
task's grant does not include, or to spend through the relay more than its
budget counts. Assume no deceptive intent — only that the easiest path gets
taken.

That party controls everything sent to the relay from inside the sandbox: a
task granted a command tool can send the relay any HTTP request it likes, with
any method, path, headers, and body, by `curl`, by `node`, or by a second agent
CLI started in the container. It also controls the provider's responses only
insofar as its request shapes them. It does not control the components the
runtime is wired with — the relay's specification, the sandbox provider, the
drivers, and the policy that names a task's tools are runtime-selected and
trusted, even where a function takes one as an argument — and it does not
control code running inside the runtime's own process or inside the relay's
container.

The invariants at stake:

- Default deny. A capability not granted in policy is unavailable. Adding one is
  an explicit, versioned edit; nothing derived may grant one.
- Fail closed. A missing check, a missing capability, or a value that cannot be
  read is a refusal, never a silent degrade or a warning that lets work
  continue. Spend the meter cannot count is refused rather than forwarded.
- Every capability claim maps to an executable assertion that fails when the
  capability is deleted.
