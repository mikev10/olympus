CONTEXT YOU NEED

The runtime drives tasks through a fixed line of stations (build, verify, review, and others). A policy grants each role a capability scope, and the scope now names a model tier (`fast`, `standard`, `deep`) for the role, may override it per station (`tierByStation`), and may grant escalation (`escalation`: `'none'`, or a failure count and a ceiling): when a task's checks keep failing, its next build iteration runs one tier higher, never past the ceiling. The runtime resolves the tier to a model through the driver, provisions each model call's sandbox with a relay — a proxy that holds the API credential and meters spending — whose price table now holds only the resolved model, so the relay refuses a request naming any other model. Each escalation is written to an enforcement record. A reviewer must not share a model family with the task's authors, and the authors are now every model that worked the task, not only the last. Separately, the Docker CLI wrapper now caps how many bytes of a command's output it holds, and the Docker provider ends the sandbox when a command passes the cap.

It must hold against a capable, motivated party trying to get a stronger, more expensive, or different model than policy grants, keep a task at a tier its record does not show, be reviewed by a model of its own family, or exhaust the host running the runtime through what a command prints. Assume no deceptive intent — only
that the easiest path gets taken.

That party controls what the model returns from a task (its result, including the model identity it reports), every file in the task's workspace and anything a command run inside the sandbox does — including which model name an HTTP request from inside the sandbox names, and how much a check or command prints — and when the runtime process stops. It does not control the components the runtime is wired with — the Vault, the sandbox provider, the relay implementation, and the drivers are runtime-selected and trusted, even where a function takes one as an argument — it does not control the policy document, which a human authors and the runtime validates, and it does not control code running inside the runtime's own process.

The invariants at stake:

- The runtime derives status; the model never reports it. Nothing a model returns may decide a task's status, its tier, which model served a call, or what a call cost.
- Default deny. A capability not granted in policy is unavailable; a per-station tier or an escalation that policy does not grant must not happen.
- Fail closed. A missing check, missing capability, malformed policy, unpriced model, unreadable or oversized output is a refusal — never a silent degrade, never a warning that lets the run continue, never a truncated result treated as complete.
- Reviewers never share the author's model family. Where the only reviewer available shares a family, the seat records reduced independence rather than claiming independence; at the highest autonomy level it is refused.
- Every capability claim maps to an executable assertion that fails when the capability is deleted.
