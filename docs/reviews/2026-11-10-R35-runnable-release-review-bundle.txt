+## Run Olympus
+
+The runtime runs as a service. The `factory-host` executable serves the HTTP
+API and is configured only from its environment. The `olympus-ai` command
+line is a client of that API and nothing more.
+
+### Supported hosts
+
+- **Linux or macOS**, with Node 22 or later, git, and a Docker daemon.
+- **Windows: WSL2 (recommended).** Run the host inside a WSL2 distribution,
+  with Docker reachable from it.
+- **Windows, native: Developer Mode required.** A run's base is copied with
+  its symbolic links kept as links, and native Windows lets a process create
+  one only with Developer Mode on (Settings, System, For developers). The
+  host checks this before it listens: it creates and removes one link under
+  `FACTORY_TREES`, and refuses to start if that fails. Links are never
+  emulated; a junction links only directories, and a link stored as a file
+  would change the hash the locks are taken over.
+
+### Install
+
+Neither package is published to npm yet. From a checkout, build, pack, and
+install both executables into an empty directory:
+
+```
+pnpm install
+node scripts/local-release.ts ~/olympus
+export PATH="$HOME/olympus/node_modules/.bin:$PATH"
+```
+
+This is the path CI tests: it installs the same tarballs npm would publish,
+then starts `factory-host` and drives it with `olympus-ai`.
+

+### Configure policy
+
+Policy decides what a run may do; anything it does not grant is unavailable.
+[examples/](examples) holds a working set, and a test admits runs under it,
+so it stays current:
+
+- [examples/policy.yaml](examples/policy.yaml): a commented policy for a
+  supervised (L1) run. It caps every run at L1; a person approves the spec,
+  the acceptance tests, and the merge; the stations between run on their
+  evidence. It declares the build and review roles, and the four drafting
+  roles a run that drafts its spec or tests needs.
+- [examples/roles/](examples/roles): the instructions for each seat. A role
+  named in the policy must have a file here. Point `FACTORY_ROLES_DIR` at a
+  copy you own, outside the repository.
+- [examples/rubrics/](examples/rubrics): what the critics of a drafting run
+  check a draft against. Point `FACTORY_RUBRICS_DIR` at a copy.
+- [examples/run/](examples/run): the files `create` reads for one small
+  change: a spec, the acceptance tests, the verification manifest
+  (`verify.json`, the checks the runtime runs, one of which must fail on the
+  base commit), the spec's security part, and the task graph.
+
+### First run
+
+The host admits runs from the working copy `FACTORY_REPOSITORY` names.
+`create --workspace` must name that same path, as an absolute path: the Vault
+locks every artifact against it, and the paths `create` is given are
+relative to it. Copy [examples/run/](examples/run) into the working copy
+(here under `run/`), and start the host with the variables above.
+
+The smallest run drafts its spec from an intent, at L1. It still needs the
+acceptance tests, the manifest, and the graph; a drafted spec has no security
+part to supply:
+
+```
+olympus-ai create --workspace /abs/path/to/repo --base-commit $(git -C /abs/path/to/repo rev-parse HEAD) \
+  --level 1 --draft-spec --intent "Add hello.txt at the repository root, saying hello." \
+  --tests run/acceptance.md --manifest run/verify.json --graph run/graph.json
+```
+
+The first `create` starts nothing. It prints the run's worst-case cost: the
+most it could spend, in US dollars, if every task used every call and every
+retry its role's `budget` allows. Approve that exact figure by running the
+same command again with `--approve-cost <usd>`. With the spec supplied
+instead, replace `--draft-spec --intent ...` with `--spec run/spec.md
+--security-part run/security.json`.
+
+Then follow it with `olympus-ai status <run id>` or `events <run id>`, and
+pass each gate the policy holds for a person with
+`olympus-ai approve <run id> <station>:1`. `olympus-ai report <run id>`
+prints what it cost and what was decided. Every command prints its flags with
+`olympus-ai <command> --help`.
+
+### Readiness
+
+`olympus-ai readiness [--revision <rev>]` asks the host to scan
+`FACTORY_REPOSITORY` at a revision (default `HEAD`) and prints the highest
+autonomy level the repository can support, with every probe's outcome and
+the probe that holds the ceiling. The scan installs and runs the repository's
+checks in sandboxes and takes minutes. It writes nothing, and admission does
+not read it yet: a run is still admitted at the level policy allows.

===== examples/roles/builder.md =====
# Builder

You build one task of a run. The message you are given is the task's id. The
task graph in your context names that task, the station it belongs to, and
the tasks it depends on.

## What you work from

Your context holds the locked spec, the acceptance tests, and the task graph.
The spec says what to build. The acceptance tests are how the change is
judged. Both were fixed before you started, and neither is yours to change.

The repository is in your working directory. Make the change there.

## What you must not do

- Do not edit the spec, the acceptance tests, the verification manifest, or
  the task graph, wherever they sit in the tree. A change to any of them is
  recorded as tampering and the task fails.
- Do not weaken, skip, delete, or regenerate a test to make it pass. Each of
  those is recorded as a finding and put in front of the person who approves
  the change.
- Do not change files outside what your task needs. A change outside the paths
  your role is granted is recorded as a violation and the run stops.
- Do not try to reach anything the session does not offer you. Tools and
  network access you were not given are unavailable by design.

## How you are judged

The runtime collects the change you leave in the tree and runs the declared
checks over it, in a sandbox you cannot reach. The result of those checks
decides the task. Nothing you say decides it.

## What to say when you finish

Your final message is recorded as your account of the work, and it is compared
with the change the runtime collected. Say what you changed and why, and say
plainly what you did not finish or could not make work. Do not describe work
you did not do.

===== examples/roles/findings-reviewer.md =====
# Findings reviewer

You review one day of the runtime's records: what its controls refused,
parked, found, and counted. The message you are given is the id of the
nightly job.

## What you work from

Your context holds every record the runtime made on one day, each with an id
the runtime gave it and its typed fields: causes, reasons, counts, stations,
runs, and tasks. Nothing a record says in words is there, and nothing anyone
outside the runtime wrote. The working directory is empty and read-only:
you cannot change anything, and you are not asked to.

## What to ask of the day

- Does one refusal, park, or failed check recur across runs or tasks, so that
  a control keeps meeting the same thing?
- Does a violation, a drifted record, or a rate that moved say something a
  person should look at?
- Do refused deliveries or a scanner's findings cluster on one source?
- Does the day show a control that should have acted and did not, a gap?

## What to say

Your final message is your review, in the form the context asks for. It is
recorded for a person to read; it does not decide anything, and nothing you
say changes a run, a grant, or a status. Every finding names one record by
its id. If you found nothing, say so with an empty list. Do not soften a
finding and do not invent one.

===== examples/roles/reviewer.md =====
# Reviewer

You review the change a run's build produced. The message you are given is the
id of the review task.

## What you work from

Your context holds the locked spec, the acceptance tests, the list of paths
the change touched, and the evidence the runtime collected for each reviewed
task: what the declared checks found over the base and over the change. The
working directory holds the repository with the change applied. It is
read-only: you cannot change anything, and you are not asked to.

## What to check

- Does the change do what the spec asks, and nothing the spec does not ask?
- Do the acceptance tests exercise the behavior the spec describes, and does
  the evidence show them failing before the change and passing after it?
- Is there anything in the change that makes a check pass without the behavior
  being there: a test weakened or skipped, a check bypassed, a special case
  for the test's input, a suppressed warning?
- Is there anything the change breaks that no check covers?

You are not shown what the author said about its work. Judge the change by
the code and the evidence.

## What to say

Your final message is your review. It is recorded beside the evidence for the
person who approves the change. For each problem, name the file and what is
wrong with it. If you found nothing wrong, say so and say what you checked. If
you could not review something, say what and why. Do not soften a finding and
do not invent one.

# Security reviewer

You review the change a run's build produced for what it does to security.
The message you are given is the id of the review task.

## What you work from

Your context holds the locked spec, with its security part where the spec has
one, the list of paths the change touched, and the evidence the runtime
collected for each reviewed task: what the declared checks, the security
checks among them, found over the base and over the change. The working
directory holds the repository with the change applied. It is read-only: you
cannot change anything, and you are not asked to.

## What to ask of the change

Ask two questions of every change.

What does it make vulnerable?

- Input that reaches a query, a command, a path, a template, or a
  deserializer without being checked.
- A secret written into the code, a log, an error, or a response.
- An authorization rule of the spec's security part that the change does not
  enforce, or enforces on one path and not another.
- A check weakened, skipped, or suppressed so that it passes.

What does it make reachable that need not be?

- An entry point, route, or code path reachable before authentication.
- An administrative, debug, or legacy surface the spec does not name.
- A default configuration that turns a control off.
- A combination of settings that weakens a control, where each setting alone
  looks safe.

You are not shown what the author said about its work. Judge the change by
the code and the evidence.

## What to say

Your final message is your review. It is recorded beside the evidence for the
person who approves the change; it does not decide anything. Every finding
names a file and a line, in the diff or in the base, and says what is wrong
there and what an attacker could do with it. If you found nothing, say so and
say what you checked. If you could not review something, say what and why. Do
not soften a finding and do not invent one.

# Spec drafter

You draft the spec for one run. The message you are given is your seat's id
and the attempt you are on. On a later attempt it also says why the last draft
went back.

## What you work from

Your context holds the intent: a person's statement of what they want. The
repository is in your working directory, so you can read how it is built,
tested, and laid out. It is a copy: nothing you change in it leaves your seat
except the four files below.

## What you write

Write exactly these four files in the one directory under `.drafts/` in your
working directory, which the runtime made for this run and left empty:

- `spec.md`: one shippable capability, in statements each of which a test can
  check. Say what the change does, and what it must not do. Cover the intent
  and nothing beyond it.
- `security.json`: the spec's security part. Either
  `{ "none": "<one line saying why the change touches no trust boundary>" }`,
  or `{ "trustBoundaries": [...], "sensitiveData": [...],
  "authorizationRules": [{ "id": "...", "rule": "..." }], "secrets": [...] }`,
  each list possibly empty. Name every authorization rule the change adds or
  relies on: each one will need a test that is refused by it.
- `run-requirements.json`: what the acceptance tests need to run, for a test
  writer who will never see this repository:
  `{ "testCommand": ["..."], "framework": "...", "testDirectory": "...",
  "publicInterface": "..." }`. `testDirectory` is where the framework finds
  acceptance tests, relative to the repository root. `publicInterface` says
  exactly what a test calls and how to reach it from a file in
  `testDirectory`: module paths, function or command names, inputs, outputs.
- `questions.json`: `{ "assumptions": [{ "point": "...", "chose": "..." }],
  "openQuestions": ["..."] }`. List each point the intent left undecided and
  what you chose. List as an open question anything you could not decide
  without guessing what the person wants.

## What you must not do

- Do not settle an open question yourself. A spec with an open question goes
  to a person; that is the right outcome, not a failure.
- Do not write tests, change the code, or write anywhere else in the tree.
  Nothing else you write is read.
- Do not reach for anything the session does not offer you.

## How you are judged

The runtime reads the four files, checks that each part parses, and records
the bytes it read. A critic checks the draft against a rubric a person wrote,
and a person or the policy decides whether it is approved. Nothing you say
decides it.

## What to say when you finish

Say what you drafted, and say plainly what you were unsure of. Do not describe
work you did not do.

# Test drafter

You write the acceptance tests for one run, from its locked spec alone. The
message you are given is your seat's id and the attempt you are on. On a later
attempt it also says why the last draft went back.

## What you work from

Your working directory holds the locked spec and nothing else: its text, its
security part, and its `run-requirements.json`, and a directory under
`.drafts/` made for this run, which may already hold the spec's files. You cannot see the repository, and nothing you do
can reach it. That is deliberate: the tests judge the capability the spec
describes, not an implementation you have seen.

## What you write

- Test files under the `testDirectory` that `run-requirements.json` names,
  each written for its `framework` and calling only the `publicInterface` it
  describes. Each test checks behavior the spec states.
- `acceptance.json`, in the directory under `.drafts/`: `{ "checks": [...] }`,
  one check per test. An `acceptance` check names its test files in `tests`;
  a `behavioral` check runs a pinned `command` that names its test file. Each check declares
  `onBase`: `"fails"` where the behavior is absent before the change, which is
  what reproduces it, and `"passes"` where the test guards something that
  holds already. At least one required check declares `"fails"`. For each
  authorization rule `security.json` names, write a test in which a caller the
  rule refuses is refused, and name the rule in that check's `deniesRule`.
- `observation.json`, in the same directory, when the run observes its
  change once merged: `{ "works": [...], "regressed": [...], "rollback":
  { "regressed": [...], "consecutive": n } }`. Each check is `{ "app",
  "name" }`: the slug of the app that runs it, such as `github-actions`, and
  the check's exact name. Name only checks the spec says the repository's CI
  runs. `works` holds the checks that pass when the change works,
  `regressed` the checks that fail when it has regressed, and `rollback`
  the indexes into `regressed` that, failing together on `consecutive`
  commits in a row, call for a rollback. A check the target never reports is
  recorded as missing, so do not invent one.

## What you must not do

- Do not test anything the spec does not state.
- Do not change the spec's files. Nothing outside the test directory and the
  manifest is read.
- Do not try to reach the repository or the network.

## How you are judged

The runtime runs your checks over the repository before any change is made,
and each must do what it declares there. If one does not, or a test path you
chose is already taken there, you learn only that your draft did not hold over
the repository: not which check, not its exit code, not which path. A
critic checks the tests against the spec and a rubric a person wrote. Nothing
you say decides it.

## What to say when you finish

Say which tests you wrote and what each checks. Do not describe work you did
not do.

export type HostConfigResult = { readonly ok: true; readonly settings: HostSettings } | { readonly ok: false; readonly problems: readonly string[] };

function declared(name: string): HostVariable | undefined {
  return HOST_VARIABLES.find((v) => (v.prefix === true ? name.startsWith(v.name) && name.length > v.name.length : v.name === name));
}

/**
 * Reads and checks the host's environment, collecting every problem rather
 * than stopping at the first. Nothing outside the table is read: asking for
 * an undeclared name is a programming error and throws.
 */
export function readHostConfig(env: Readonly<Record<string, string | undefined>>): HostConfigResult {
  const problems: string[] = [];
  const get = (name: string): string => {
    if (declared(name) === undefined) throw new Error(`factory-host: ${name} is read but not declared in HOST_VARIABLES`);
    return env[name] ?? '';
  };
  const required = (name: string): string => {
    const value = get(name);
    if (value === '') problems.push(`${name} is not set: ${declared(name)?.purpose ?? ''}`);
    return value;
  };
  const optional = (name: string): string | null => {
    const value = get(name);
    return value === '' ? null : value;
  };
  // Each check that throws is caught here and listed, so one bad pair does not hide the rest.
  const checked = <T>(read: () => T, fallback: T): T => {
    try {
      return read();
    } catch (error) {
      problems.push((error instanceof Error ? error.message : String(error)).replace(/^factory-host: /u, ''));
      return fallback;
    }
  };

  const token = required('FACTORY_API_TOKEN');
  const portText = required('FACTORY_LISTEN_PORT');
  const port = Number(portText);
  if (portText !== '' && (!/^\d+$/u.test(portText) || port > 65535)) problems.push(`FACTORY_LISTEN_PORT is not a port: ${portText}`);

/**
 * The start-up check that the trees directory can hold a symbolic link
 * (R35, #28, #123). A run's base is copied with its links kept as links, so a
 * host that cannot create one fails mid-run, at admission, with `EPERM`. This
 * check creates and removes one file link under `FACTORY_TREES` before the
 * host listens, on every platform, so the refusal follows the capability and
 * not a guess about the operating system (I5).
 *
 * Emulating links is rejected (#28): a junction links directories only, and a
 * link stored as a file changes the content hash the locks are taken over.
 */
import { mkdir, mkdtemp, readlink, rm, symlink, writeFile } from 'node:fs/promises';
import { join } from 'node:path';

export type MakeLink = (target: string, path: string) => Promise<void>;

const fileLink: MakeLink = (target, path) => symlink(target, path, 'file');

/** Null when a link was created, read back, and removed; otherwise the refusal, naming the remedy. */
export async function probeSymlinks(trees: string, makeLink: MakeLink = fileLink): Promise<string | null> {
  let dir: string | null = null;
  try {
    await mkdir(trees, { recursive: true });
    dir = await mkdtemp(join(trees, '.symlink-probe-'));
    await writeFile(join(dir, 'target'), 'probe');
    await makeLink('target', join(dir, 'link'));
    const read = await readlink(join(dir, 'link'));
    if (read !== 'target') return `FACTORY_TREES (${trees}) does not keep a symbolic link as written: it read back ${JSON.stringify(read)}`;
    return null;
  } catch (error) {
    const code = typeof error === 'object' && error !== null && 'code' in error ? String(error.code) : 'error';
    return [
      `FACTORY_TREES (${trees}) cannot hold a symbolic link (${code}), and every run's base is copied with its links kept.`,
      'On Windows, run the host under WSL2 (recommended), or enable Developer Mode so a process can create links;',
      'see README.md, "Supported hosts"',
    ].join(' ');
  } finally {
    if (dir !== null) await rm(dir, { recursive: true, force: true });
  }
}

/**
 * Readiness reachable from the host (R35, #125): R1's scan over the host's
 * working copy at one revision, with the host's own sandbox provider, check
 * image, limits, and sandbox user, the policy's protected paths, and a GitHub
 * branch-protection checker. It writes nothing, and admission does not read
 * its ceiling: enforcing it there is its own decision (out of scope).
 */
import { NPM_REGISTRY, resolveCommit, scan, SECRET_SCAN_IMAGE, type BranchProtectionChecker, type ReadinessReport } from '@olympus-ai/readiness';
import type { BuiltGraph } from './graph.js';
import { loadPolicyFile } from './policy-file.js';

/** Resolves a revision first, so a bad one is refused before a stream opens, then scans that commit. */
export interface ReadinessScanner {
  resolve(revision: string): Promise<string>;
  scan(commit: string): Promise<ReadinessReport>;
}

export interface ReadinessScannerOptions {
  readonly components: BuiltGraph;
  /** The working copy runs are admitted from: `FACTORY_REPOSITORY`. Read, never written. */
  readonly repository: string;
  /** Read at each scan, as each run's admission reads it, for its protected paths. */
  readonly policyFile: string;
  readonly branchProtection: BranchProtectionChecker | null;
}

/** The wall clocks R1's own end-to-end fixture runs a real repository under. */
const TIMEOUTS = { installMs: 300_000, probeMs: 180_000, coldProvisionMs: 60_000 } as const;

export function readinessScanner(options: ReadinessScannerOptions): ReadinessScanner {
  const { profile } = options.components;
  if (profile === null) throw new Error('readiness: the host has no sandbox profile, so a scan has no image to run in');
  return {
    resolve: (revision) => resolveCommit(options.repository, revision),
    scan: async (commit) => {
      const loaded = await loadPolicyFile(options.policyFile);
      // No policy, no protected paths to probe against: refused rather than scanned against none (I5).
      if (!loaded.ok) throw new Error(`readiness: the policy file is refused (${loaded.code}): ${loaded.message}`);
      const { policy } = loaded;
      return scan({
        checkout: options.repository,
        revision: commit,
        provider: options.components.sandbox,
        // Node with npm and corepack: the image the line's checks run the stack's tools in.
        image: profile.checkImage,
        secretScanImage: SECRET_SCAN_IMAGE,
        limits: profile.limits,
        user: options.components.workspaces.user,
        timeouts: TIMEOUTS,
        registries: NPM_REGISTRY,
        protectedPaths: policy.protectedPaths,
        branchProtection: options.branchProtection,
      });
    },
  };
}

const REPOSITORY = /^[A-Za-z0-9_.-]+\/[A-Za-z0-9_.-]+$/u;

/**
 * Whether GitHub protects the integration branch: the `protected` field of
 * `GET /repos/{owner}/{repo}/branches/{branch}`, which read access answers.
 * Any other answer throws, which the probe records as indeterminate (I5).
 */
export class GitHubBranchProtection implements BranchProtectionChecker {
  readonly name: string;
  readonly #url: string;
  readonly #token: string;

  constructor(options: { readonly repository: string; readonly branch: string; readonly token: string; readonly apiBase?: string }) {
    if (!REPOSITORY.test(options.repository)) throw new Error(`readiness: ${options.repository} is not owner/name`);
    if (options.branch === '' || options.token === '') throw new Error('readiness: a branch-protection checker needs a branch and a token');
    this.name = `github:${options.repository}@${options.branch}`;
    this.#url = `${(options.apiBase ?? 'https://api.github.com').replace(/\/+$/u, '')}/repos/${options.repository}/branches/${encodeURIComponent(options.branch)}`;
    this.#token = options.token;
  }

  async check(): Promise<{ readonly protected: boolean; readonly detail: string }> {
    const res = await fetch(this.#url, {
      headers: { authorization: `Bearer ${this.#token}`, accept: 'application/vnd.github+json', 'x-github-api-version': '2022-11-28' },
      signal: AbortSignal.timeout(30_000),
    });
    if (!res.ok) throw new Error(`GitHub answered ${String(res.status)} for ${this.name}`);
    const body: unknown = await res.json();
    const value = typeof body === 'object' && body !== null ? (body as { protected?: unknown }).protected : undefined;
    if (typeof value !== 'boolean') throw new Error(`GitHub's answer for ${this.name} has no protected field`);
    return { protected: value, detail: value ? `${this.name} is a protected branch` : `${this.name} is not protected` };
  }
}

/**
 * Readiness reachable (R35, #125): `GET /readiness` runs the scanner it is
 * given over one revision and streams its report; a bad revision is refused
 * before the stream opens, and a server with no scanner refuses the route.
 * The scanner itself is R1's `scan`, tested in its own package; here it is a
 * stand-in, so this suite proves the route and nothing about the probes.
 */
import { afterEach, beforeEach, describe, expect, test } from 'vitest';
import type { ReadinessReport } from '@olympus-ai/readiness';
import { createApiServer, GitHubBranchProtection, type ApiServer, type ReadinessScanner } from '../src/index.js';
import { makeWorkspace, policyDocument, removeWorkspace, ROLES, stubComponents } from './harness.js';
import { writeFile } from 'node:fs/promises';

const TOKEN = 't'.repeat(40);
const COMMIT = 'a'.repeat(40);
const REPORT = { commit: COMMIT, ceiling: { kind: 'scanned', level: 1, commit: COMMIT }, probes: [], skipped: [], collectedBy: 'runtime' } as unknown as ReadinessReport;

let workspace: string;
let server: ApiServer | undefined;
let url: string;

beforeEach(async () => {
  workspace = await makeWorkspace('r35-readiness-');
});

afterEach(async () => {
  await server?.close();
  server = undefined;
  await removeWorkspace(workspace);
});

async function serve(readiness: ReadinessScanner | null): Promise<void> {
  const policyFile = `${workspace}.policy.yaml`;
  await writeFile(policyFile, JSON.stringify(policyDocument()));
  server = createApiServer({ components: stubComponents(workspace), token: TOKEN, principal: 'local', policyFile, rolesDirectory: ROLES, readiness });
  url = await server.listen(0, '127.0.0.1');
}

async function get(path: string): Promise<{ status: number; type: string | null; text: string }> {
  const res = await fetch(`${url}${path}`, { headers: { authorization: `Bearer ${TOKEN}` } });
  return { status: res.status, type: res.headers.get('content-type'), text: await res.text() };
}

describe('GET /readiness', () => {
  test('streams the commit, then the report for the revision asked for', async () => {
    const asked: string[] = [];
    await serve({ resolve: (rev) => { asked.push(rev); return Promise.resolve(COMMIT); }, scan: (commit) => Promise.resolve({ ...REPORT, commit }) });
    const res = await get('/readiness?revision=main');
    expect(res.status).toBe(200);
    expect(res.type).toMatch(/^text\/event-stream/u);
    expect(asked).toEqual(['main']);
    expect(res.text).toContain(`event: started\ndata: ${JSON.stringify({ revision: 'main', commit: COMMIT })}`);
    expect(res.text).toContain(`event: report\ndata: ${JSON.stringify(REPORT)}`);
  });

  test('scans HEAD when no revision is named', async () => {
    const asked: string[] = [];
    await serve({ resolve: (rev) => { asked.push(rev); return Promise.resolve(COMMIT); }, scan: () => Promise.resolve(REPORT) });
    expect((await get('/readiness')).status).toBe(200);
    expect(asked).toEqual(['HEAD']);
  });

  test('a revision that names no commit is refused before anything is scanned', async () => {
    let scanned = false;
    await serve({ resolve: () => Promise.reject(new Error("readiness: /repo has no commit 'nope'")), scan: () => { scanned = true; return Promise.resolve(REPORT); } });
    const res = await get('/readiness?revision=nope');
    expect(res.status).toBe(400);
    expect(JSON.parse(res.text)).toMatchObject({ error: 'bad-request', message: expect.stringContaining('no commit') as unknown });
    expect(scanned).toBe(false);
  });

  test('a scan that fails ends the stream with failed, never a report', async () => {
    await serve({ resolve: () => Promise.resolve(COMMIT), scan: () => Promise.reject(new Error('the policy file is refused')) });
    const res = await get('/readiness');
    expect(res.text).toContain('event: failed');
    expect(res.text).not.toContain('event: report');
  });

  test('a server with no scanner refuses the route', async () => {
    await serve(null);
    const res = await get('/readiness');
    expect(res.status).toBe(409);
    expect(JSON.parse(res.text)).toMatchObject({ error: 'refused' });
  });

  test('the route needs the token, and only GET', async () => {
    await serve({ resolve: () => Promise.resolve(COMMIT), scan: () => Promise.resolve(REPORT) });
    expect((await fetch(`${url}/readiness`)).status).toBe(401);
    expect((await fetch(`${url}/readiness`, { method: 'POST', headers: { authorization: `Bearer ${TOKEN}` } })).status).toBe(405);
  });
});

  test('reads the branch\'s protected field, and throws on any other answer', async () => {
    const answers: Array<{ status: number; body: unknown }> = [{ status: 200, body: { protected: true } }, { status: 200, body: { protected: false } }, { status: 404, body: {} }, { status: 200, body: {} }];

      expect(seen[0]).toBe('/repos/o/r/branches/main Bearer tok');
    } finally {
      await new Promise((done) => { api.close(done); });
    }
  });

  const lines: string[] = [];
  const errors: string[] = [];
  const calls: string[] = [];
  return {
    lines, errors, calls, env: {},
    fetch: ((url: URL | string) => { calls.push(String(url)); return Promise.resolve(new Response('{}', { status: 200 })); }) as typeof fetch,

===== packages/conformance/src/registry/release.ts =====
/**
 * `I9.packaged-host-runs` (R35, #55): the one supported way to run, tested as
 * a user runs it. `scripts/local-release.ts` builds every released package,
 * packs each as npm would publish it, and installs the tarballs into an empty
 * directory. Then, from that install and nothing in the checkout:
 *
 * - every installed `bin` names JavaScript the tarball holds;
 * - `factory-host`, started from its `bin` with nothing set, refuses with
 *   every required variable in one list, no stack frame, and a non-zero exit,
 *   before it listens (I5);
 * - `factory-host`, configured with the shipped examples, listens, headless,
 *   and `olympus-ai`, started from its own `bin` as a separate process, reaches
 *   it over HTTP and nothing else (I9).
 *
 * A `bin` pointing at TypeScript, a missing shebang, a file the tarball does
 * not ship, an install that reaches back into the checkout, or a refusal that
 * prints a stack fails here.
 */
import { spawn, type ChildProcess } from 'node:child_process';
import { randomBytes } from 'node:crypto';
import { existsSync, readFileSync } from 'node:fs';
import { cp, mkdir, mkdtemp, rm, writeFile } from 'node:fs/promises';
import { createServer } from 'node:net';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { workspaceRoot } from '../kit/workspace.js';

const BUILD_MS = 600_000;
const LISTEN_MS = 600_000;
/** Required variables a refusal must name; the table in packages/api/src/host/config.ts is their source. */
const REQUIRED = [
  'FACTORY_API_TOKEN', 'FACTORY_LISTEN_PORT', 'FACTORY_POLICY_FILE', 'FACTORY_ROLES_DIR', 'FACTORY_VAULT_STORE',
  'FACTORY_REPOSITORY', 'FACTORY_TREES', 'ANTHROPIC_API_KEY', 'FACTORY_GIT_REPOSITORY', 'FACTORY_GIT_BASE_BRANCH', 'FACTORY_GIT_TOKEN',
];

interface Ran { readonly code: number | null; readonly stdout: string; readonly stderr: string }

/** The variables a child process needs to find node, git, and Docker, and nothing of the factory's. */
function baseEnv(): Record<string, string> {
  const env: Record<string, string> = {};
  for (const key of ['PATH', 'Path', 'SystemRoot', 'TEMP', 'TMP', 'HOME', 'USERPROFILE', 'APPDATA', 'LOCALAPPDATA', 'DOCKER_HOST', 'DOCKER_CONFIG', 'ProgramFiles', 'ComSpec']) {
    const value = process.env[key];
    if (value !== undefined) env[key] = value;
  }
  return env;
}

function run(command: string, args: readonly string[], options: { cwd?: string; env?: Record<string, string>; timeoutMs: number }): Promise<Ran> {
  return new Promise((resolveRan, reject) => {
    const child = spawn(command, [...args], { cwd: options.cwd, env: options.env ?? baseEnv(), stdio: ['ignore', 'pipe', 'pipe'] });
    let stdout = '';
    let stderr = '';
    child.stdout.on('data', (chunk: Buffer) => { stdout += chunk.toString('utf8'); });
    child.stderr.on('data', (chunk: Buffer) => { stderr += chunk.toString('utf8'); });
    const timer = setTimeout(() => { child.kill(); reject(new Error(`I9: ${command} ${args.join(' ')} did not finish in ${String(options.timeoutMs)} ms`)); }, options.timeoutMs);
    child.on('error', reject);
    child.on('close', (code) => { clearTimeout(timer); resolveRan({ code, stdout, stderr }); });
  });
}

/** The file an installed package's `bin` names, which must be JavaScript the tarball shipped. */
function installedBin(install: string, pkg: string, name: string): string {
  const dir = join(install, 'node_modules', ...pkg.split('/'));
  const manifest = JSON.parse(readFileSync(join(dir, 'package.json'), 'utf8')) as { bin?: Record<string, string> };
  const target = manifest.bin?.[name];
  if (target === undefined) throw new Error(`I9: the installed ${pkg} has no bin named ${name}`);
  if (!target.endsWith('.js')) throw new Error(`I9: the installed ${pkg}'s bin ${name} is ${target}, not JavaScript`);
  const file = join(dir, target);
  if (!existsSync(file)) throw new Error(`I9: the installed ${pkg}'s bin ${name} names ${target}, which the tarball does not hold`);
  if (!readFileSync(file, 'utf8').startsWith('#!/usr/bin/env node\n')) throw new Error(`I9: ${pkg}'s bin ${name} has no node shebang, so it cannot be run as a command`);
  return file;
}

function freePort(): Promise<number> {
  return new Promise((resolvePort, reject) => {
    const server = createServer();
    server.once('error', reject);
    server.listen(0, '127.0.0.1', () => {
      const address = server.address();
      const port = typeof address === 'object' && address !== null ? address.port : 0;
      server.close(() => { resolvePort(port); });
    });
  });
}

async function git(cwd: string, ...args: string[]): Promise<void> {
  const ran = await run('git', ['-c', 'user.name=conformance', '-c', 'user.email=conformance@invalid', ...args], { cwd, timeoutMs: 60_000 });
  if (ran.code !== 0) throw new Error(`I9: git ${args.join(' ')} exited ${String(ran.code)}: ${ran.stderr}`);
}

export async function assertPackagedHostRuns(): Promise<void> {
  const root = workspaceRoot();
  const dir = await mkdtemp(join(tmpdir(), 'r35-release-'));
  let host: ChildProcess | undefined;
  try {
    const install = join(dir, 'install');
    const released = await run(process.execPath, [join(root, 'scripts', 'local-release.ts'), install], { cwd: root, env: { ...baseEnv() }, timeoutMs: BUILD_MS });
    if (released.code !== 0) throw new Error(`I9: the local release failed\n${released.stderr}`);
    const hostBin = installedBin(install, '@olympus-ai/api', 'factory-host');
    const cliBin = installedBin(install, 'olympus-ai', 'olympus-ai');
    if (hostBin.startsWith(root) || cliBin.startsWith(root)) throw new Error('I9: an installed bin resolves into the checkout');

    // Nothing set: one refusal naming every required variable, no frame, a non-zero exit.
    const refused = await run(process.execPath, [hostBin], { cwd: dir, timeoutMs: 60_000 });
    if (refused.code === 0) throw new Error('I9: factory-host started with nothing set');
    const missing = REQUIRED.filter((name) => !refused.stderr.includes(`${name} is not set`));
    if (missing.length > 0) throw new Error(`I9: the refusal does not name ${missing.join(', ')}\n${refused.stderr}`);
    if (/^\s+at /mu.test(refused.stderr)) throw new Error(`I9: the refusal prints a stack trace\n${refused.stderr}`);
    if (!refused.stderr.includes('.env.example')) throw new Error(`I9: the refusal does not say where the variables are described\n${refused.stderr}`);

    // Configured from the shipped examples: the host listens and the CLI reaches it.
    const repository = join(dir, 'repo');
    await mkdir(repository);
    await git(repository, 'init', '--quiet', '--initial-branch=main');
    await writeFile(join(repository, 'README.md'), 'a repository for the packaged-host assertion\n');
    await git(repository, 'add', 'README.md');
    await git(repository, 'commit', '--quiet', '-m', 'base');
    await cp(join(root, 'examples', 'roles'), join(dir, 'roles'), { recursive: true });
    const token = randomBytes(24).toString('hex');
    const port = await freePort();
    const env: Record<string, string> = {
      ...baseEnv(),
      FACTORY_API_TOKEN: token, FACTORY_LISTEN_PORT: String(port), FACTORY_POLICY_FILE: join(root, 'examples', 'policy.yaml'),
      FACTORY_ROLES_DIR: join(dir, 'roles'), FACTORY_VAULT_STORE: join(dir, 'store'), FACTORY_REPOSITORY: repository, FACTORY_TREES: join(dir, 'trees'),
      ANTHROPIC_API_KEY: 'unused-no-run-is-started', FACTORY_GIT_REPOSITORY: 'example/unused', FACTORY_GIT_BASE_BRANCH: 'main', FACTORY_GIT_TOKEN: 'unused',
      // A host with no uids names who sandboxes run as (D-I1b-10); one with them derives it.
      ...(process.getuid === undefined ? { FACTORY_CONTAINER_UID: '1000', FACTORY_CONTAINER_GID: '1000' } : {}),
    };
    let hostErr = '';
    const started = spawn(process.execPath, [hostBin], { cwd: dir, env, stdio: ['ignore', 'ignore', 'pipe'] });
    host = started;
    started.stderr.on('data', (chunk: Buffer) => { hostErr += chunk.toString('utf8'); });
    const url = `http://127.0.0.1:${String(port)}`;
    const cli = (...args: string[]): Promise<Ran> => run(process.execPath, [cliBin, ...args, '--url', url, '--token', token], { cwd: dir, env: baseEnv(), timeoutMs: 60_000 });
    const deadline = Date.now() + LISTEN_MS;
    for (;;) {
      if (started.exitCode !== null) throw new Error(`I9: the configured factory-host exited ${String(started.exitCode)}\n${hostErr}`);
      const ran = await cli('outcomes');
      if (ran.code === 0) {
        JSON.parse(ran.stdout);
        break;
      }
      if (Date.now() > deadline) throw new Error(`I9: factory-host did not answer within ${String(LISTEN_MS)} ms\n${ran.stderr}\n${hostErr}`);
      await new Promise((r) => setTimeout(r, 1000));
    }
    const unknown = await cli('status', 'no-such-run');
    if (unknown.code !== 1 || !unknown.stderr.includes('error 404')) throw new Error(`I9: the CLI did not report the host's 404 for an unknown run\n${unknown.stderr}`);
    const help = await run(process.execPath, [cliBin, 'create', '--help'], { cwd: dir, env: baseEnv(), timeoutMs: 60_000 });
    if (help.code !== 0 || !help.stdout.includes('--workspace')) throw new Error(`I9: the installed CLI's create --help failed\n${help.stderr}`);
  } finally {
    if (host?.exitCode === null) {
      const exited = new Promise((r) => host?.once('exit', r));
      host.kill();
      await exited;
    }
    await rm(dir, { recursive: true, force: true });
  }
}

===== scripts/local-release.ts =====
/**
 * The one supported way to run Olympus from a checkout (R35, #55): build every
 * released package to JavaScript, pack each as npm would publish it, and
 * install the tarballs into an empty directory. The result is what a user
 * gets from the registry: `node_modules/.bin/factory-host` and
 * `node_modules/.bin/olympus-ai`, both JavaScript, neither reaching back into
 * the checkout.
 *
 *     node scripts/local-release.ts <empty directory>
 *
 * The conformance assertion `I9.packaged-host-runs` runs this script and then
 * the two executables it installed, so the path a user follows is the path
 * that is tested. Publishing to npm is the maintainer's and is not done here.
 */
import { spawnSync } from 'node:child_process';
import { existsSync, mkdirSync, readdirSync, readFileSync, rmSync, writeFileSync } from 'node:fs';
import { dirname, join, resolve } from 'node:path';
import { fileURLToPath } from 'node:url';

const ROOT = resolve(dirname(fileURLToPath(import.meta.url)), '..');

export interface ReleasedPackage {
  readonly name: string;
  readonly dir: string;
}

/** Every workspace package with a `build` script: the packages the release ships. */
export function releasedPackages(root: string = ROOT): ReleasedPackage[] {
  const out: ReleasedPackage[] = [];
  for (const parent of [join(root, 'packages'), join(root, 'packages', 'drivers')]) {
    for (const entry of readdirSync(parent, { withFileTypes: true })) {
      const file = join(parent, entry.name, 'package.json');
      if (!entry.isDirectory() || !existsSync(file)) continue;
      const pkg = JSON.parse(readFileSync(file, 'utf8')) as { name?: unknown; scripts?: Record<string, unknown> };
      if (typeof pkg.name === 'string' && typeof pkg.scripts?.build === 'string') out.push({ name: pkg.name, dir: join(parent, entry.name) });
    }
  }
  return out;
}

function run(command: string, args: readonly string[], cwd: string): string {
  // One command line, each argument quoted: on Windows pnpm and npm are .cmd shims that only a shell starts.
  const line = [command, ...args.map((a) => JSON.stringify(a))].join(' ');
  const result = spawnSync(line, { cwd, shell: true, encoding: 'utf8', maxBuffer: 64 * 1024 * 1024 });
  if (result.status !== 0) {
    throw new Error(`local-release: ${command} ${args.join(' ')} exited ${String(result.status)} in ${cwd}\n${result.stdout}${result.stderr}`);
  }
  return result.stdout;
}

/**
 * Builds, packs, and installs into `target`, which must be absent or empty:
 * a directory that already holds an install could hide a file the tarballs
 * lack. Every workspace package is installed from its tarball by `overrides`,
 * so none is looked up on the registry by name (D-R35-05).
 */
export function localRelease(target: string, root: string = ROOT): void {
  const dest = resolve(target);
  if (existsSync(dest) && readdirSync(dest).length > 0) throw new Error(`local-release: ${dest} is not empty`);
  const packages = releasedPackages(root);
  if (packages.length === 0) throw new Error('local-release: no workspace package has a build script');
  // A file deleted from src/ must not survive in dist/ from an earlier build.
  for (const pkg of packages) rmSync(join(pkg.dir, 'dist'), { recursive: true, force: true });
  run('pnpm', ['build'], root);
  const tarballs = join(dest, 'tarballs');
  mkdirSync(tarballs, { recursive: true });
  const deps: Record<string, string> = {};
  for (const pkg of packages) {
    const before = new Set(readdirSync(tarballs));
    run('pnpm', ['pack', '--pack-destination', tarballs], pkg.dir);
    const made = readdirSync(tarballs).filter((f) => !before.has(f));
    if (made.length !== 1 || made[0] === undefined) throw new Error(`local-release: packing ${pkg.name} made ${String(made.length)} tarballs`);
    deps[pkg.name] = `file:./tarballs/${made[0]}`;
  }
  writeFileSync(join(dest, 'package.json'), `${JSON.stringify({ name: 'olympus-local-release', private: true, dependencies: deps, overrides: deps }, null, 2)}\n`);
  run('npm', ['install', '--no-audit', '--no-fund', '--loglevel=error'], dest);
}

if (process.argv[1] !== undefined && resolve(process.argv[1]) === fileURLToPath(import.meta.url)) {
  const target = process.argv[2];
  if (target === undefined || target === '') {
    process.stderr.write('usage: node scripts/local-release.ts <empty directory>\n');
    process.exitCode = 2;
  } else {
    try {
      localRelease(target);
      process.stdout.write(`installed into ${resolve(target)}: node_modules/.bin/factory-host and node_modules/.bin/olympus-ai\n`);
    } catch (error) {
      process.stderr.write(`${error instanceof Error ? error.message : String(error)}\n`);
      process.exitCode = 1;
    }
  }
}
