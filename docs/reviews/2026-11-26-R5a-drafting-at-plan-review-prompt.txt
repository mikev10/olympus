CONTEXT YOU NEED

The runtime carries a change through fixed stations: intake, spec, test-design, plan, build, verify, review, integrate. Until this change, the task graph (which build tasks exist, under which role, in what order, and which review covers them) was a file a person supplied, hashed at admission and locked at `plan`. This change lets a run be admitted with the literal 'draft' in place of that file. A model seated as "planner" at `plan` then reads the locked spec and the repository and writes one file, `.drafts/<run id>/graph.json`, holding build tasks only. The runtime reads that file, records the bytes, checks them against a bound a person wrote into policy (`planning`: the most build tasks, and the roles they may run under), adds one review task itself, has a second model (the "plan critic") read the draft, and puts the draft through the station's approval gate. Only an approved draft is written into the artifact root and locked, and only then are the tasks created and builders seated. Because no graph exists at admission, admission's checks that used to read the graph (which roles are compiled and granted, what the trigger admits, and the worst-case cost a person approves) now read the bound instead. Each drafted task also carries an `objective`, text the planner wrote, which is placed in a builder's context. The commit range also carries one earlier, unrelated change to a local test script under `scripts/`.

It must hold against a capable, motivated party trying to get more work, a wider role, or a weaker review than a person granted and approved: a graph run that was not the one approved, a task seated under a role policy did not allow, a run costing more than the approved figure, a review that does not cover the work, or instructions reaching a seat that is not granted them.
