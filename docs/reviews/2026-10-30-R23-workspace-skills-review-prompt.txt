CONTEXT YOU NEED

The project runs coding agents in a sequence of seats over one repository working tree, inside a Docker sandbox. Each seat must run under the instructions its role supplies and nothing else, because an agent can write files into the tree the next seat runs over. Two drivers exist: one runs the Claude Code CLI inside the sandbox, the other runs its own agent loop against an OpenAI-compatible endpoint. This change extends the Claude Code driver's assertion to cover skills (`.claude/skills/<id>/SKILL.md` and `.agents/skills/<id>/SKILL.md`) with and without the `Skill` tool granted, adds a control that reruns the driver's own invocation without the `--setting-sources ''` flag and must see the planted skill, adds an equivalent assertion for the OpenAI-compatible driver (requests sent over a planted workspace must be byte-identical to those over an empty one), and adds a registry check that every package under `packages/drivers/` owns such an assertion.

The Claude Code assertion makes real model calls and runs only in CI with a credential. The OpenAI-compatible assertion calls no model; its endpoint is a scripted test server that logs every request body. Assertions are registered in `packages/conformance/src/registry`; an `external` entry counts only when the owning package's own test run reports the test with that exact id and title passing.

It must hold against a capable, motivated party trying to make these assertions pass while a driver does load an instruction file from the working tree. Assume no deceptive intent — only that the easiest path gets taken.

That party controls the files in the working tree (the workspace mount), what the model writes in its reply, and, for future work, the source of a new driver package. It does not control the components the runtime is wired with — the sandbox provider, the relay that holds the model credential, the CLI version pinned in the image, and the conformance kit's reconciliation of test reports are trusted — and it does not control code running inside the test runner's own process.

The invariants at stake:

- An agent may not be judged by, or instructed by, an artifact it can write. Instruction files planted in the working tree must not reach the next seat's session.
- Fail closed. A missing check, a control that cannot see what it guards, or a session that did not run is a refusal, never a pass.
- Every capability claim maps to an executable assertion that fails when the capability is deleted. Removing `--setting-sources ''` from the Claude Code driver's command line must turn its assertion red.

The mechanisms that matter most:

- The Claude Code assertion: two driver sessions (no tools; `Skill` granted), checked on the reply text and on the CLI's own `init` skill list, and the control that reruns the recorded `Skill` invocation with one flag removed.
- The test harness's recording of each exec's argv and environment, and the exec it exposes for the control, which must stay metered beside the driver's calls.
- The OpenAI-compatible assertion's byte comparison of request bodies between a bare and a planted workspace.
- `workspaceInstructionProblems` and `I3.every-driver-has-a-workspace-instruction-assertion`: discovery of driver packages and the table check.
