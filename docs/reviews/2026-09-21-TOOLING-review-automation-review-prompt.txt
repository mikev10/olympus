CONTEXT YOU NEED

A maintainer runs this command-line runner once per reviewer family to send a
committed code bundle, together with a committed prompt, to a third-party model
for adversarial review. For the Codex family it spawns OpenAI's Codex CLI with
the prompt and the bundle inlined into one text on its stdin, in a scratch
configuration directory built for the run; for the Gemini family it makes a
direct HTTPS call to Google's Gemini API that offers the model no tools. Either
way it writes the reply, a manifest and a stripped session log into a directory
that is committed to version control, and derives a single outcome for each run
from the facts it recorded; the files under `.claude/skills/` describe how a
maintainer operates it.

It must hold against a capable, motivated party trying to make the runner send
a bundle it should have refused, record a run as counted when it should not
count, or place a credential into a committed file. Assume no deceptive intent
— only that the easiest path gets taken.

That party controls everything the third-party model returns — the reply text,
and the content of the vendor's session log and API response — and the content
of the bundle itself, which is the code under review and may contain any string,
including text shaped like instructions. It does not control the maintainer's
machine, the git repository and its history (the bundle's content is the
party's; the repository it is committed to is not), the installed CLI binaries,
the runner's own process, or the environment the maintainer launches the runner
with. Those are trusted even where a function takes one as a parameter — a
repository root, a home directory, an environment map, or a git, filesystem or
process function passed in as a dependency.

The invariants at stake:

Fail closed. A missing check, a missing credential, an unsupported platform or
an ambiguous result is a refusal — never a silent degrade, never a warning that
lets the run continue.

Default deny. A capability or a value that is not explicitly allowed is
unavailable.

Status is derived, never reported. A run's outcome is computed from the facts
the runner recorded. No caller sets it, and it is never taken from what the
model says about its own work.

Payloads are data, never instructions. Content that arrives from outside the
process never enters a prompt as an instruction.

The mechanisms that matter most:

- The refusals that run before anything is sent, and the order they run in
  (`prepare`, `runCodex` and `runGemini` in `scripts/run-external-review.ts`).
- The two integrity checks: an echo of four markers read from the committed
  bundle — its BASE and HEAD values, its final section path, and a random end
  nonce on its last line — and the vendor-reported input-token count checked
  against a floor of the payload's size in bytes divided by five.
- The outcome derivation: one outcome per run, computed from the facts recorded
  in its manifest.
- The handling of the two credentials: a Gemini API key read from the
  environment, and Codex OAuth tokens copied into the scratch directory for the
  run and, if the run refreshed them, written back to the maintainer's real
  credential file; and the scan of every evidence file for either before
  anything is written.
