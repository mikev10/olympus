# Decisions: R37

## R37: A failed gate tells the retry, and the run, why

Started on `v2` at 1a34231, after R29 (#153). Issues #158, #159.

### D-R37-01: boundary, verified

- **Deliverables:**
  - A build task's next iteration after a failed gate carries, in its
    variable suffix, each failed required check's id and the cause the gate
    derived, as typed parts the runtime builds, never a byte of the check's
    output (#159).
  - `LastFailure` becomes a union of the attempt failure and the gate
    failure; `lastFailureOf` returns the parked task's latest of the two,
    whatever it parked on; a check that did not start carries the reason
    its evidence recorded, trimmed, as untrusted text (#158).
  - `events` publishes a `gate-failed` event when the line records one (#158).
  - One free assertion per fix, each failing with its fix reverted (I8).
- **Out of scope (verbatim):** telling a retry anything the container
  printed; a retry message for review seats; raising `maxIterations`, or
  changing how iterations are counted; the host's log sink, which waits on
  #132 (D-R36a-13).
- **Acceptance:** `pnpm -r typecheck`, `pnpm -r lint`, `pnpm -r test` pass;
  each new assertion is shown failing with its fix reverted and passing with
  it. Paid suites run in CI under `run-driver`, as for every unit.
- **Invariants:** I3 (the suffix names only checks of the locked manifest,
  which the builder already reads and cannot write); I7 (no check output,
  and no evidence reason, enters a prompt; the reason reaches `status` and
  `events` only, as untrusted text); I8 (each fix has an assertion that fails
  when it is reverted); I2 (the cause is the gate's derivation, read from
  the runtime's records, never the model's account).
- **Pending registry entries owed:** none name R37. Assertions are added;
  the baseline is unchanged.
- **Gate paths touched, all declared:** `packages/conformance/`. The suffix
  builder goes in `packages/core/src/station/machine.ts`, which no protected
  pattern matches; no `types.ts` changes (D-R37-03). The PR needs the
  `gate-change` label and the squash body `Gate-Change: acknowledged`.

### D-R37-02: assumptions, each verified

- The build retry carries only the task id today: `build` calls `runTask`
  with `{ inputs }` and no `suffix` (`packages/api/src/line.ts:1445`), and
  the suffix is `[task.id, suffix?, ...inputs]` (`line.ts:1076`).
- Every failed gate records a `station-refused` decision whose refusal is
  `gate-failed` and lists each failed check's id and cause, at every
  iteration, before the status is committed (`line.ts:1723-1727`). The
  P14 row `station:gate-failed` asserts one per iteration.
- `FailedCheck.cause` is a closed union of six literals
  (`packages/core/src/station/types.ts:61`); check ids come from the locked
  verification manifest, which is hashed before build (I3), so neither is
  text the builder or its container produced.
- `lastFailureOf` reads only `attempt-failed` decisions, and returns null
  unless the park is `retries-exhausted` (`packages/api/src/run.ts:1920-1930`).
- `events` publishes only `state`, `standing`, `attempt-failed`, `end`
  (`packages/api/src/http/wire.ts:94-99`); the only hook the line calls on a
  failure is `onAttemptFailed` (`line.ts:216`, `line.ts:762`).
- A check that did not start is in the evidence bundle's `unstarted`, with
  a reason that can be `describe(error)` of a sandbox or container failure
  (`line.ts:1603-1656`, `packages/vault/src/types.ts:121`); the evidence
  ref is committed with the same iteration's status, the park included
  (`line.ts:1729-1731`).
- A conflict records `task-conflict` and sends the task back to build
  without a gate (`line.ts:1397-1404`); `gatedIterations` excludes it
  (`packages/core/src/policy/tier.ts:35`).
- No CLI code and no api test reads `LastFailure` (grep over
  `packages/cli/src` and `packages/*/test`); its one reader outside
  `run.ts` is the P14 `attempt-failed` row
  (`packages/conformance/src/registry/decisions.ts:812`).
- R36a (172c3cd, `reviewed/R36a`) and R19 (`reviewed/R19`) are merged.

### D-R37-03: the retry reads the failure from the Vault; a builder of its own in `core`

- **Where the retry learns the failed checks.** Chosen: the build reads the
  task's decisions and, when its latest verify outcome is a `gate-failed`
  decision (not a later `task-conflict`), passes that decision's checks.
  Only when the task has a gated iteration behind it, so a first build reads
  nothing. Rejected: holding the failure in the line's memory, which a
  resume in another process loses; re-deriving it from the evidence bundle,
  which repeats the gate's logic and can drift from what it recorded;
  adding it to `RunState`, a contract change. Reversal: replace the read
  with any of those.
- **After a conflict, nothing is told.** The iteration a conflict sent back
  was judged by no gate (D-R4-03), so an older gate failure is not the
  cause of this retry. Reversal: take the latest gate decision regardless.
- **The suffix's shape.** Chosen: `gateRetrySuffix(failed)` in
  `packages/core/src/station/machine.ts`, taking `FailedCheck`s and writing
  `[failed-checks]` then `- <checkId>: <cause>` per check, and nothing of
  `exitCode`. Rejected: a new `RetryPart` kind, since `retrySuffix` and its
  parts are a drafter's and a build retry must not be able to receive
  `notes` or critic findings; it would also edit `types.ts`, a protected
  path, for no gain. Reversal: add the kind and route through `retrySuffix`.
- **`LastFailure`'s union.** A `kind` discriminant, `attempt-failed` or
  `gate-failed`, after the decision causes. The gate arm carries
  `failed: { checkId, cause, untrustedReason }[]`, the reason non-null only
  for a `no-result` check, taken from the latest evidence bundle of the task
  and trimmed to `FAILURE_DETAIL_LIMIT` like `untrustedDetail`. Read for any
  park that names a task, not only `retries-exhausted`.
- **The event's shape.** `gate-failed` carries the same gate arm as
  `status`, built by the line from the failures and the `unstarted` it holds,
  so a reader of either sees one shape. No host log line: the host's log
  sink is out of scope.
